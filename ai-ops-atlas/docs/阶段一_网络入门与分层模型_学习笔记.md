## 1. 网络到底是什么

### 1.1 从一个具体问题开始

先别急着背定义。想一个具体场景：

> 你的电脑和隔壁同事的电脑，中间只隔了一堵墙。你要传一个 100 MB 的文件给他，怎么做最快？

答案大概率是：插一根网线，或者走公司局域网。但你有没有想过，这根网线里到底跑了什么？"文件"是怎么变成能在线里跑的东西的？

再想一层：你打开浏览器输入 `www.baidu.com`，几毫秒后页面出来了。中间隔着十几台你不认识的设备、上千公里的光纤。**为什么这些设备彼此不认识、厂商不同、系统不同，却还能顺畅地传递数据？**

这两个问题的答案，就是整个计算机网络的全部内容。而这一阶段要解决的，是其中最基础的那一层——**"大家约定好怎么说话"**。

### 1.2 网络的定义与组成

**计算机网络（Computer Network）**：把地理位置不同的、具有独立功能的多台计算机（或设备），通过通信线路连接起来，在网络操作系统和通信协议的管理协调下，实现资源共享和信息传递的系统。

这句话里有两个关键词：

- **通信线路**：物理上的连接，网线、光纤、无线电波都算。
- **通信协议**：逻辑上的约定，也就是"说话规矩"。**没有协议，连线等于没连。**

一个网络的组成可以拆成三块：

| 组成 | 说明 | 例子 |
|---|---|---|
| 硬件 | 负责"传" | 网卡、交换机、路由器、网线、光纤 |
| 软件 | 负责"管" | 操作系统网络栈、协议实现、网络管理软件 |
| 协议 | 负责"约" | TCP/IP、HTTP、以太网协议 |

> 💡 **术语解释｜协议（Protocol）**
> 网络中的"协议"就是一套通信双方都必须遵守的规则集合。它规定了**用什么格式发、发什么内容、按什么顺序发、出错怎么办**。人和人说话要遵守语法，计算机之间通信要遵守协议。协议不是法律，而是"事实上的约定"——大家都这么做，所以能通。

### 1.3 网络边缘与网络核心

这是理解互联网结构的一个关键切分，来自经典教材《计算机网络：自顶向下方法》。

```
┌─────────────────────────────────────────────┐
│              网络边缘（Edge）                 │
│   主机 / 端系统：PC、手机、服务器、IoT 设备     │
│   运行各种应用：浏览器、微信、邮件客户端         │
└─────────────────────────────────────────────┘
                     ↕
┌─────────────────────────────────────────────┐
│              网络核心（Core）                 │
│   由大量路由器互联构成的网状网络                 │
│   唯一职责：为边缘提供连通性，负责转发数据         │
└─────────────────────────────────────────────┘
```

- **网络边缘（Edge）**：也叫**端系统（End System）**，指所有接入网络的终端设备。真正产生和消费数据的是它们。
- **网络核心（Core）**：由路由器（Router）互联组成的骨干网络。它不关心你传的是图片还是文字，**只负责把数据从一头搬到另一头**。

这个切分很重要，因为后面所有的协议分工，本质上都是"边缘的事"和"核心的事"的分工。

> 💡 **术语解释｜主机（Host）/ 端系统（End System）**
> 指网络中能收发数据的终端设备。注意"主机"在计算机网络里**不等于**服务器，你的手机、笔记本都是主机。

### 1.4 三种交换方式：数据怎么从 A 走到 B

网络核心到底怎么转发数据？历史上出现过三种方案。

#### ① 电路交换（Circuit Switching）

**先建立一条独占的物理通路，再传输，传完释放。**

最典型的例子是**传统电话网**：你拨号，交换局给你和对方之间接一条专用线路；通话期间这条线路只有你们俩能用；挂断，线路释放。

- ✅ 优点：时延固定且小，传输连续，适合实时语音
- ❌ 缺点：**资源独占**。你没说话的时候线路也空占着，利用率极低；而且建立连接需要时间

#### ② 报文交换（Message Switching）

**不建连接，把整个报文作为一个整体，一站一站地存储转发。**

- ✅ 优点：不用独占线路
- ❌ 缺点：报文可能很大，一个路由器要完整收完才能转发，**时延大，且对路由器存储要求高**

#### ③ 分组交换（Packet Switching）—— 现代互联网的基础

**把大块数据切成一个个小"分组"（Packet），每个分组独立地一站一站转发。**

分组的好处在于：路由器收到一个分组就可以立刻转发出去，不用等整块数据；不同分组甚至可能走不同路径，最后在目的地重新组装。

- ✅ 优点：
  - **高效**：多个用户的分组可以共享同一条链路（叫**统计复用**），线路利用率高
  - **灵活**：某个链路坏了，分组可以绕路
  - **迅速**：不必等整个报文到达
- ❌ 缺点：
  - 每个分组要额外加**首部（Header）**，有开销
  - 网络拥塞时会产生**排队时延**，极端情况下**丢包**

> 💡 **术语解释｜分组（Packet，又译"包"）**
> 把长数据切成的若干小数据块，每个块前面加上控制信息（首部）。首部里通常包含"从哪来、到哪去、属于哪个连接"等信息。**互联网的本质就是"分组交换网络"。**

**三者对比一览：**

| 对比项 | 电路交换 | 报文交换 | 分组交换 |
|---|---|---|---|
| 是否需建立连接 | 需要 | 不需要 | 不需要 |
| 资源占用 | 独占 | 共享 | 共享 |
| 时延特性 | 固定、小 | 大 | 小但波动（有排队） |
| 线路利用率 | 低 | 中 | 高 |
| 典型场景 | 传统电话网 | 早期电报 | 互联网 |

### 1.5 网络的分类：按覆盖范围

| 类型 | 全称 | 覆盖范围 | 典型技术 |
|---|---|---|---|
| **PAN** | Personal Area Network 个人区域网 | 约 10 米 | 蓝牙、NFC、ZigBee |
| **LAN** | Local Area Network 局域网 | 约 1 公里内（一栋楼/一个园区） | 以太网、Wi-Fi |
| **MAN** | Metropolitan Area Network 城域网 | 约 10 公里（一座城市） | 光纤环网、城域以太网 |
| **WAN** | Wide Area Network 广域网 | 跨城市、跨国家 | 专线、MPLS、SD-WAN |

**互联网（Internet）** 不是上面某一种，而是**把全世界各种 LAN、MAN、WAN 互联起来形成的"网络的网络"（network of networks）**。

### 1.6 两种通信模式：C/S 与 P2P

| 模式 | 全称 | 工作方式 | 优点 | 缺点 | 例子 |
|---|---|---|---|---|---|
| **C/S** | Client/Server 客户/服务器 | 客户端主动请求，服务器被动响应 | 管理集中、易维护 | 服务器是瓶颈，成本高 | 网站、微信 |
| **P2P** | Peer-to-Peer 对等连接 | 每台主机既是客户端又是服务器 | 可扩展性强、成本低 | 管理困难、安全性差 | BitTorrent、区块链 |

> 💡 **术语解释｜客户端（Client）与服务器（Server）**
> 这是**角色**而不是**设备**。同一台电脑，你浏览网页时它是客户端，你用 Python 起一个 HTTP 服务时它就是服务器。判断标准是"谁主动发起请求"。

## 2. 为什么必须分层

### 2.1 一个类比：寄快递

这是理解分层最直观的方式。假设你要给外地的朋友寄一个杯子：

| 步骤 | 你实际做的事 | 对应的网络层次 |
|---|---|---|
| 1 | 想好要寄什么、写张纸条 | 应用层 |
| 2 | 把杯子用气泡膜包好、贴上易碎标签 | 表示层 |
| 3 | 跟快递员约好上门取件时间 | 会话层 |
| 4 | 选"保价+签收"，确保完整送达 | 传输层 |
| 5 | 快递公司规划走陆运还是空运、中转哪几个城市 | 网络层 |
| 6 | 每个中转站扫描、贴分拣标签，确保不上错车 | 数据链路层 |
| 7 | 卡车在高速上实际跑 | 物理层 |

关键在于：**每一层只关心自己的事，不需要知道别的层怎么干。**

- 你不需要知道卡车走哪条高速（物理层细节）
- 快递公司不需要知道你寄的是杯子还是书（应用层内容）
- 中转站只认标签，不认内容（数据链路层只认 MAC 地址）

**这就是分层的全部精髓：把复杂问题拆成若干个独立的小问题，每层只解决一个。**

### 2.2 分层带来的四个好处

1. **降低复杂度**：每一层只需关注自己的职责，出错时也只需在层内排查
2. **标准化**：只要接口约定好，不同厂商的实现可以互通（这是互联网能建成的根本原因）
3. **易于更新**：底层从铜缆换成光纤，上层应用完全无感
4. **便于排障**：网络故障可以按层定位——"是物理层断了还是应用层配错了？"

### 2.3 分层的两条铁律：对等通信 + 层间接口

这是最容易理解错的地方，务必记牢：

> **铁律一（对等通信）**：不同设备的**同一层**之间，按照同一套协议进行**逻辑通信**。
> **铁律二（层间接口）**：同一设备内部，相邻层之间通过**接口**进行交互，上层只能调用直接下层的服务，不能越层。

举个例子：你电脑的 HTTP 协议，只会和**服务器的 HTTP 协议**对话；你电脑的 TCP 层，只会和**服务器的 TCP 层**对话。

**你的 HTTP 层绝不会直接跟服务器的 TCP 层说话。**

看起来像"你的 HTTP 直接跟服务器 HTTP 通信"（那条虚线），但实际数据必须先一层层往下走，穿过物理介质，再一层层往上去（那些实线）。

```
   你的电脑                              服务器
┌────────────┐                      ┌────────────┐
│   应用层    │ ← —— 逻辑上对话 —— → │   应用层    │
├────────────┤                      ├────────────┤
│   传输层    │ ← —— 逻辑上对话 —— → │   传输层    │
├────────────┤                      ├────────────┤
│   网络层    │ ← —— 逻辑上对话 —— → │   网络层    │
├────────────┤                      ├────────────┤
│ 数据链路层  │ ← —— 逻辑上对话 —— → │ 数据链路层  │
├────────────┤                      ├────────────┤
│   物理层    │ ←———— 真实的数据流 ————→│   物理层    │
└────────────┘                      └────────────┘
```

> 💡 **术语解释｜接口（Interface）**
> 相邻两层之间交换信息的"约定通道"。它规定了下层向上层提供哪些操作、上层怎么调用。接口是**垂直**的（同一台机器内），协议是**水平**的（跨机器）。

### 2.4 协议的三要素

前面说"协议就是规矩"。具体来说，一个完整的协议必须包含三个要素：

| 要素 | 英文 | 含义 | 通俗解释 |
|---|---|---|---|
| **语法** | Syntax | 数据与控制信息的结构或格式 | "话怎么说"——先说什么、后说什么、格式如何 |
| **语义** | Semantics | 需要发出何种控制信息、完成何种动作、做出何种应答 | "话是什么意思"——收到请求该回什么 |
| **时序** | Timing | 事件实现顺序的详细说明 | "什么时候说"——先握手再传数据 |

举例：TCP 三次握手就同时体现了这三要素——SYN/ACK 是语法（报文格式），"收到 SYN 要回 SYN+ACK"是语义，而"必须先握手才能传数据"就是时序。

### 2.5 协议、服务、接口：三个容易混的概念

| 概念 | 面向 | 说明 |
|---|---|---|
| **协议** | 水平（对等层之间） | 本层内部如何实现自己的功能 |
| **服务** | 垂直（下层向上层） | 下层为上层提供的能力，**只有功能描述，不暴露实现** |
| **接口** | 垂直（相邻层之间） | 上层访问下层服务的入口 |

一句话总结：**协议是本层的事，服务是下层给上层的事，接口是两者之间的门。**

## 3. OSI 七层参考模型

### 3.1 它是怎么来的

上世纪六七十年代，各家厂商各自为政：IBM 有 SNA，DEC 有 DECnet，互相不兼容。不同厂商的设备想互通，得专门做网关，成本极高且无法复用。

1984 年，**国际标准化组织（ISO）** 发布了 **OSI 参考模型（Open Systems Interconnection Reference Model，开放系统互连参考模型）**，试图给全世界一套统一的网络体系标准。

> 💡 **术语解释｜ISO 与 OSI**
> - **ISO**（International Organization for Standardization）是国际标准化组织，是**制定标准的机构**。
> - **OSI** 是 ISO 发布的那个**模型本身**。
> - 注意别把 OSI 写成"ISO 七层模型"，这是常见笔误。

有一个关键事实要记住：**OSI 是"先有模型，后设计协议"**——属于理论指导实践。而真正统治互联网的 TCP/IP 是"先有协议，后总结模型"。这就是为什么 OSI 学起来漂亮，但现实中几乎没人真的按它去实现。

### 3.2 七层逐层详解

从下往上（因为数据是从下往上"长"出来的），每层都给出：**一句话职责 / 详细功能 / 典型协议 / 典型设备 / 数据单元 / 类比**。

---

#### 第 1 层：物理层（Physical Layer）

- **一句话职责**：把 0 和 1 变成能在介质上跑的电压、光信号或电磁波。
- **详细功能**：
  - 定义接口的**机械特性**（接口长什么样、几根针）
  - 定义**电气特性**（多少伏表示 1，多少伏表示 0）
  - 定义**功能特性**（每根线干什么）
  - 定义**规程特性**（信号变化的时序）
  - 确定传输速率、传输模式（单工/半双工/全双工）
- **典型协议/标准**：RS-232、V.35、RJ-45 接口标准、光纤标准
- **典型设备**：中继器、集线器（Hub）、网线、光纤、无线收发器、网卡（物理部分）
- **数据单元**：**比特（bit）**
- **类比**：高速公路本身和跑在上面的卡车

> ⚠️ 物理层的故障最典型的表现是**信号衰减**（线太长信号变弱）和**串扰**（相邻线对互相干扰）。这类问题**改 IP、配 VLAN 都没用**，必须先查物理链路——这是排障的第一原则。

---

#### 第 2 层：数据链路层（Data Link Layer）

- **一句话职责**：把一串裸比特切成"帧"，用 MAC 地址在**同一链路内**找到邻居，并保证这一跳不出错。
- **详细功能**：
  - **成帧与解帧**：在比特流中标记出"一个数据单元的起止"
  - **物理寻址**：用 MAC 地址标识设备
  - **差错检测**：帧尾加 CRC 校验，发现错误就丢弃
  - **流量控制**：防止发得太快把对方淹没
  - **介质访问控制**：多台设备共享一条线路时，决定谁先发
- **两个子层**：
  - **LLC（逻辑链路控制）**：负责帧同步、流量控制、差错控制，对上屏蔽不同介质的差异
  - **MAC（介质访问控制）**：负责控制对物理介质的访问，提供 MAC 地址
- **典型协议**：以太网（Ethernet，IEEE 802.3）、Wi-Fi（IEEE 802.11）、PPP、HDLC、VLAN（802.1Q）
- **典型设备**：**交换机（Switch）**、网桥（Bridge）、网卡
- **数据单元**：**帧（Frame）**
- **类比**：每个中转站的扫描、分拣、贴标签

> 💡 **术语解释｜MAC 地址**
> Media Access Control Address，也叫**物理地址**。48 位（6 字节），通常写成 `00-1A-2B-3C-4D-5E` 这种形式。前 3 字节是厂商编号（OUI），后 3 字节是厂商自己分配的序列号。**理论上全球唯一，出厂即固化**（虽然可以软件修改）。可以把它理解为网卡的"身份证号"。

---

#### 第 3 层：网络层（Network Layer）

- **一句话职责**：负责**跨网络**的数据转发，决定数据包从源到目的走哪条路。
- **详细功能**：
  - **逻辑寻址**：分配 IP 地址（和 MAC 地址不同，IP 是逻辑的、可变的）
  - **路由选择**：为数据包选择路径（由路由协议完成）
  - **分组转发**：把数据包从入接口转发到出接口
  - **分片与重组**：数据包超过链路 MTU 时切分
  - **拥塞控制**（部分实现）
- **典型协议**：IP、ICMP、IGMP、路由协议（RIP / OSPF / BGP）
- **典型设备**：**路由器（Router）**、三层交换机
- **数据单元**：**分组 / 包（Packet）**
- **类比**：快递公司规划走哪条路线、中转哪几个城市

> 💡 **术语解释｜MTU（Maximum Transmission Unit，最大传输单元）**
> 一条链路能承载的**单个数据帧的最大长度**。以太网默认 MTU 是 **1500 字节**。数据包比 MTU 大就要**分片**，分片会带来额外开销，所以工程上常把 MTU 调优作为一个性能手段。

> ⚠️ **关于 ARP 的层次归属**：ARP（地址解析协议，负责把 IP 地址解析成 MAC 地址）在不同教材里归属不一，有的归网络层，有的归数据链路层。**比较准确的说法是它工作在"第 2.5 层"**——它用网络层的地址，产生数据链路层的数据。考试时按教材写，理解时知道它跨两层即可。

---

#### 第 4 层：传输层（Transport Layer）

- **一句话职责**：为**两台主机上的具体应用程序**之间提供端到端的通信服务。
- **详细功能**：
  - **端口寻址**：用端口号区分同一台主机上的不同应用
  - **分段与重组**：把上层数据切成合适大小的段
  - **连接管理**：建立、维护、释放连接（TCP）
  - **可靠传输**：确认、重传、排序（TCP）
  - **流量控制**：滑动窗口
  - **拥塞控制**：慢启动、拥塞避免（TCP）
  - **差错检测**
- **典型协议**：**TCP**、**UDP**
- **典型设备**：四层防火墙、四层负载均衡器、网关
- **数据单元**：TCP 叫**段（Segment）**，UDP 叫**用户数据报（Datagram）**
- **类比**：选"保价 + 签收"服务，确保包裹完整送达并可追踪

> 💡 **术语解释｜端口号（Port Number）**
> 16 位数字（0～65535），用来标识一台主机上的**具体应用程序**。IP 地址负责"找到哪台机器"，端口号负责"找到机器上的哪个程序"。两者配合，才能把数据送到正确的进程。常见端口：80（HTTP）、443（HTTPS）、53（DNS）、22（SSH）。

---

#### 第 5 层：会话层（Session Layer）

- **一句话职责**：管理和控制**两个应用之间的对话（会话）**——建立、维持、终止。
- **详细功能**：
  - 会话建立、维护与终止
  - **对话控制**：决定谁先说、谁后说（半双工/全双工管理）
  - **同步**：在数据流中插入检查点，断了可以从检查点续传，不用从头来
- **典型协议/技术**：RPC（远程过程调用）、NetBIOS、SQL 会话、NFS
- **数据单元**：数据（Data）
- **类比**：跟快递员约好上门取件的时间

> ⚠️ **重点提醒**：OSI 的会话层和表示层，在现实中**几乎没有独立实现**。它们的职能要么并入了应用层，要么由应用程序自己处理。所以 TCP/IP 模型直接把它们合并进了应用层。**学这两层是为了理解"为什么要分层"，而不是为了找它们对应的设备。**

---

#### 第 6 层：表示层（Presentation Layer）

- **一句话职责**：负责数据的**格式转换、加密解密、压缩解压**，保证不同系统之间能互相看懂。
- **详细功能**：
  - **数据格式转换**：如字符编码转换（ASCII ↔ Unicode ↔ GBK）
  - **数据加密与解密**
  - **数据压缩与解压**
- **典型技术**：JPEG、GIF、MPEG、ASCII/Unicode、TLS/SSL（部分职责）
- **数据单元**：数据（Data）
- **类比**：把杯子用气泡膜包好、贴上格式化的易碎标签

---

#### 第 7 层：应用层（Application Layer）

- **一句话职责**：**直接面向用户和应用程序**，提供网络服务的接口。
- **详细功能**：
  - 为各种网络应用提供协议支持
  - 处理用户请求的具体业务细节
  - 文件传输、邮件、网页、域名解析、远程登录等
- **典型协议**：HTTP/HTTPS、FTP、SMTP/POP3/IMAP、DNS、DHCP、Telnet、SSH、SNMP
- **数据单元**：数据（Data）
- **类比**：快递员把包裹最终交到你手上

> 💡 **术语解释｜应用层 ≠ 应用程序**
> 这是初学者最容易混的点。**浏览器（Chrome）是应用程序，HTTP 协议才是应用层协议。** 应用层是"协议"的集合，不是"软件"的集合。你写的 Web 程序在应用层工作，但程序本身不是应用层。

---

### 3.3 七层速记口诀

**从下往上**：物、数、网、传、会、表、应

**记忆口诀（任选一个）**：

- 物数网传会表应
- **"Please Do Not Throw Sausage Pizza Away"**（Physical, Data link, Network, Transport, Session, Presentation, Application）
- **"All People Seem To Need Data Processing"**（从上往下：Application → Physical）

### 3.4 七层不是平等的：1-4 层 vs 5-7 层

OSI 七层有一个重要的分界：

| 分组 | 层次 | 关注点 | 面向对象 |
|---|---|---|---|
| **低四层**（1-4） | 物理、数据链路、网络、传输 | **数据传输**：怎么把数据可靠地从 A 搬到 B | 网络工程师 |
| **高三层**（5-7） | 会话、表示、应用 | **数据处理与服务**：数据怎么被理解和呈现 | 应用开发者 |

**记住这个分界，你就能明白为什么面试官问"四层负载均衡和七层负载均衡有什么区别"——前者只看 IP 和端口，后者能看懂 HTTP 内容。**

## 4. TCP/IP 四层模型

### 4.1 它是怎么来的

TCP/IP 的诞生比 OSI 更早，也更"草根"。

1969 年，美国国防部高级研究计划局（**ARPA**）建立了 **ARPANET**，这是互联网的前身。为了让它能工作，研究者们陆续设计了 IP、TCP 等协议。到 1983 年 ARPANET 全面切换到 TCP/IP 协议族，这套体系就此定型。

后来人们把它总结成**四层模型**（也叫 **DoD 模型**，Department of Defense Model）。

关键区别：**TCP/IP 是"先有协议，后总结模型"**——模型是对既成事实的描述，而不是设计蓝图。

### 4.2 四层详解

| 层 | 名称 | 职责 | 对应协议 |
|---|---|---|---|
| 4 | **应用层**（Application） | 为用户应用提供网络服务 | HTTP、HTTPS、DNS、DHCP、FTP、SMTP、SSH |
| 3 | **传输层**（Transport） | 端到端通信、可靠传输 | TCP、UDP |
| 2 | **网络层**（Internet，也叫网际层/IP 层） | 逻辑寻址与路由转发 | IP、ICMP、IGMP、ARP |
| 1 | **网络接口层**（Network Interface，也叫链路层/网络访问层） | 物理介质访问与链路传输 | 以太网、Wi-Fi、PPP |

> 💡 **术语解释｜协议栈（Protocol Stack）**
> 指按层次组织起来的一整套协议。因为协议是"堆叠"起来的（上层依赖下层），所以叫"栈"。你常听到的"TCP/IP 协议栈"，指的就是这一整套东西，而不只是 TCP 和 IP 两个协议。

### 4.3 与 OSI 的对应关系

```
      OSI 七层模型                    TCP/IP 四层模型
┌──────────────────┐
│     应用层        │ ┐
├──────────────────┤ │
│     表示层        │ ├──────→  ┌──────────────────┐
├──────────────────┤ │         │      应用层       │
│     会话层        │ ┘         └──────────────────┘
├──────────────────┤
│     传输层        │ ─────────→  ┌──────────────────┐
├──────────────────┤            │      传输层       │
│     网络层        │ ─────────→  └──────────────────┘
├──────────────────┤            ┌──────────────────┐
│   数据链路层      │ ┐           │      网络层       │
├──────────────────┤ ├──────→   └──────────────────┘
│     物理层        │ ┘          ┌──────────────────┐
└──────────────────┘            │    网络接口层     │
                                └──────────────────┘
```

**对应关系总结（务必背下来）：**

| OSI | TCP/IP |
|---|---|
| 应用层 + 表示层 + 会话层 | **应用层** |
| 传输层 | **传输层** |
| 网络层 | **网络层（网际层）** |
| 数据链路层 + 物理层 | **网络接口层** |

### 4.4 五层模型：教学用的折中方案

因为 OSI 的会话层/表示层在现实中没用，而 TCP/IP 把物理层和数据链路层合在一起又不够清晰，所以**教材里最常用的是五层模型**：

**应用层 → 传输层 → 网络层 → 数据链路层 → 物理层**

> 📌 **重要提醒**：看到"五层模型"不要慌，它不是什么新东西，就是 **OSI 的低五层**，只是把会话层和表示层砍掉了。**学网络时用五层模型最方便，理解架构时用 OSI，看实际协议时用 TCP/IP 四层。**

### 4.5 为什么 TCP/IP 赢了 OSI

| 对比项 | OSI | TCP/IP |
|---|---|---|
| 出现顺序 | 先有模型，后有协议 | 先有协议，后总结模型 |
| 实用性 | 理论完美，实现复杂 | 实用优先，先跑起来再说 |
| 会话/表示层 | 独立成层，现实中无人实现 | 合并进应用层，务实 |
| 市场地位 | 被标准组织背书 | 被真实互联网验证 |
| 现状 | 学习用的参考模型 | 事实上的工业标准 |

**一句话结论：OSI 是"最好的教材"，TCP/IP 是"最好的产品"。**

## 5. 数据封装与解封装（本阶段最核心）

如果说前面是"静态的层次图"，那么封装就是"动态的过程图"。**这一节理解了，后面学 HTTP、TCP、IP 会轻松十倍。**

### 5.1 先认识 PDU

> 💡 **术语解释｜PDU（Protocol Data Unit，协议数据单元）**
> 每一层对"自己这一层处理的数据块"的称呼。同一份数据，走到不同层，名字就不一样。**这是面试高频考点。**

| 层次 | PDU 名称 | 中文 |
|---|---|---|
| 应用层 | Message | 报文 |
| 传输层（TCP） | Segment | 段 |
| 传输层（UDP） | Datagram | 用户数据报 |
| 网络层 | Packet | 分组 / 包 |
| 数据链路层 | Frame | 帧 |
| 物理层 | Bit | 比特 |

### 5.2 发送方：封装（Encapsulation）

**核心规则：数据每往下走一层，就在前面"套"一个该层的首部（Header）。**

```
应用层：  [              数据 Data                ]
              ↓ 加 TCP 首部
传输层：  [TCP头][         数据        ]          → 段 Segment
              ↓ 加 IP 首部
网络层：  [IP头][TCP头][     数据     ]           → 包 Packet
              ↓ 加帧头 + 帧尾
链路层：  [帧头][IP头][TCP头][数据][帧尾FCS]      → 帧 Frame
              ↓ 转成电信号
物理层：  010101110100101011010...                → 比特流 Bit
```

**每层加的东西：**

| 层 | 加什么 | 关键内容 |
|---|---|---|
| 传输层 | TCP/UDP 首部 | 源端口、目的端口、序号、标志位 |
| 网络层 | IP 首部 | 源 IP、目的 IP、TTL、协议号 |
| 数据链路层 | 帧头 + 帧尾 | 源 MAC、目的 MAC、类型、CRC 校验 |
| 物理层 | 不加首部 | 把帧转成信号发出去 |

> 💡 **术语解释｜首部（Header）与尾部（Trailer）**
> 首部加在数据**前面**，存放控制信息；尾部加在数据**后面**，主要用于差错校验（如以太网帧的 FCS）。绝大多数层只加首部，**只有数据链路层既加首部又加尾部**。

### 5.3 接收方：解封装（Decapsulation）

接收方是**反过来**的过程——每往上一层，就剥掉一层首部：

```
物理层：  收到比特流，还原成帧
              ↓ 剥掉帧头帧尾，校验 CRC
链路层：  检查目的 MAC 是不是自己 → 是则上交
              ↓ 剥掉 IP 首部
网络层：  检查目的 IP 是不是自己 → 是则上交
              ↓ 剥掉 TCP 首部
传输层：  根据目的端口找到对应应用
              ↓ 组装数据
应用层：  交给浏览器/微信，显示给用户
```

### 5.4 一个完整实例：ping 一下百度

```
你执行：ping www.baidu.com
```

| 步骤 | 发生了什么 | 涉及层次 |
|---|---|---|
| 1 | 应用层生成 ICMP 回显请求报文 | 应用层 |
| 2 | 系统查 DNS，把域名解析成 IP 地址 | 应用层（DNS） |
| 3 | 查路由表，确定下一跳 | 网络层 |
| 4 | 查 ARP 缓存（或发 ARP 请求），得到网关的 MAC 地址 | 网络层 / 链路层 |
| 5 | 逐层封装成帧，通过网卡发出 | 全部层次 |
| 6 | 数据包经过多个路由器逐跳转发 | 网络层 |
| 7 | 百度服务器收到后逐层解封装，生成回显应答 | 全部层次 |
| 8 | 应答包按同样流程回到你电脑 | 全部层次 |
| 9 | 终端显示 `时间=xx ms`，这个时间就是 RTT | 应用层 |

**这个例子把"分层 + 封装 + 性能指标"全串起来了。** 建议你亲手做一遍（见第 9 节实践任务）。

### 5.5 封装带来的开销：一个容易被忽略的点

每次封装都加首部，就意味着**有额外的流量开销**：

- TCP 首部 20 字节 + IP 首部 20 字节 = **至少 40 字节**
- 以太网 MTU 是 1500 字节，所以每个包最多能装 **1460 字节**的纯数据（这叫 **MSS**）

> 💡 **术语解释｜MSS（Maximum Segment Size，最大报文段长度）**
> TCP 一个段里能携带的**最大数据量**。MSS = MTU − IP 首部 − TCP 首部 = 1500 − 20 − 20 = **1460 字节**（以太网典型值）。
> **MTU 是链路层的限制，MSS 是传输层的限制。** 两者经常被混淆，注意区分。

## 6. 网络性能指标

这一节是"量化网络"的部分，也是考试和面试的常客。**公式不多，但要理解物理含义。**

### 6.1 速率与带宽

**速率（Rate）**：又叫数据率、比特率，指主机在数字信道上**每秒能传送多少比特**。

- 单位：`b/s`、`kb/s`、`Mb/s`、`Gb/s`、`Tb/s`
- 换算：**1 Tb/s = 10³ Gb/s = 10⁶ Mb/s = 10⁹ kb/s = 10¹² b/s**（注意是 **10 的幂**，不是 1024）

**带宽（Bandwidth）**：在计算机网络中，指**网络设备支持的最高数据传输速率**。

- 单位同上：`b/s`、`Mb/s` 等
- 注意：带宽是**理论最大值**，不是实际速度

> ⚠️ **一个必须搞清的坑：bit 与 Byte**
>
> - **速率用 bit（比特）**：100 Mbps = 100 兆比特每秒
> - **存储用 Byte（字节）**：1 Byte = 8 bit
> - **所以 100 Mbps 的宽带，理论最大下载速度 = 100 ÷ 8 = 12.5 MB/s**
>
> 这就是为什么"100M 宽带"下载只有十几 MB/s——**运营商说的是 bit，下载软件显示的是 Byte。** 这是最常见的认知误区之一。

另外注意：

- **速率单位**用 10 的幂：1 Mb/s = 10⁶ b/s
- **存储单位**传统用 2 的幂：1 MB = 1024 KB = 2²⁰ B
- （严格来说，现代标准里 KiB/MiB 才是 1024，KB/MB 应是 1000，但中文教材和日常习惯仍广泛使用 KB = 1024 B）

### 6.2 吞吐量

**吞吐量（Throughput）**：单位时间内**实际通过**某个网络的数据量。

- 单位同样是 `b/s` 等
- **关键关系：吞吐量 ≤ 带宽**（受带宽限制，还受链路质量、拥塞、协议开销等影响）

**一句话区分带宽和吞吐量：带宽是"水管有多粗"，吞吐量是"实际流过去多少水"。**

### 6.3 时延（Delay / Latency）

**时延**：数据从网络一端传送到另一端所花的时间。单位是秒（s）或毫秒（ms）。

**时延由四部分组成：**

| 类型 | 英文 | 含义 | 公式 |
|---|---|---|---|
| **发送时延** | Transmission Delay | 把数据块的**所有比特推上链路**所需时间 | `发送时延 = 数据长度 ÷ 信道带宽` |
| **传播时延** | Propagation Delay | 电磁波在**介质中跑完链路长度**所需时间 | `传播时延 = 链路长度 ÷ 电磁波传播速度` |
| **处理时延** | Processing Delay | 路由器/主机**处理分组**的时间（提取首部、检错、查表） | 无固定公式 |
| **排队时延** | Queuing Delay | 分组在路由器**等待可用输出链路**的时间 | 无固定公式，随负载变化 |

**总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延**

> ⚠️ **最容易搞混的两个**：
> - **发送时延**取决于**数据长度和带宽**（数据越多、带宽越小，发送越慢）
> - **传播时延**取决于**距离和介质中的光速**（和带宽**完全无关**）
>
> **"带宽再大，也快不过光速。"** 卫星通信带宽可以很大，但传播时延摆在那里（约 120 ms 单程），这是物理限制。

### 6.4 时延带宽积

**时延带宽积 = 传播时延 × 带宽**，单位是**比特（bit）**。

**物理意义：这条链路"能装多少个比特"——也就是"管道容量"。**

想象一根水管：传播时延是"水从这头流到那头要多久"，带宽是"管子多粗"。两者相乘，就是"整根管子里同时能装多少水"。

- 例：传播时延 20 ms，带宽 100 Mb/s
- 时延带宽积 = 0.02 s × 100 × 10⁶ b/s = **2 × 10⁶ bit = 2 Mbit**

**这个指标对理解 TCP 窗口大小至关重要**——如果发送窗口小于时延带宽积，链路就填不满，性能上不去。

### 6.5 往返时延 RTT

**RTT（Round-Trip Time，往返时延）**：从发送方发出数据，到**收到接收方确认**，总共经历的时间。

**RTT 包含：**

- 2 × 传播时延（去 + 回）
- 接收方的处理时延
- 中间路由器的转发处理时延

**RTT 不包含**：发送方的发送时延、发送方自身的处理时延。

> 📌 **小数据包场景下**：`RTT ≈ 2 × 传播时延`。这就是为什么 `ping` 显示的"时间"通常约等于两地之间的往返传播时延——它直接反映了物理距离。

### 6.6 利用率与丢包率

**信道利用率** = 有数据通过的时间 ÷ 总时间

**网络利用率** = 所有信道利用率的加权平均值

**时延与利用率的关系（重要）：**

> **利用率越高，时延越大。** 当利用率接近 100% 时，时延会急剧上升——这就是**网络拥塞**。

这就是为什么网络设计不能追求"把带宽用满"，一般建议核心链路利用率控制在 70% 以下。

**丢包率**：丢失的分组数 ÷ 发送的分组总数。反映网络拥塞程度和链路质量。

### 6.7 一道计算例题

> **题目**：一条链路长 1000 km，带宽 100 Mb/s，电磁波在介质中的传播速度为 2 × 10⁸ m/s。现在要发送一个 1000 Byte 的数据包，求总时延（忽略处理时延和排队时延）。

**第一步：统一单位**

- 数据长度 = 1000 Byte = 1000 × 8 = **8000 bit**
- 带宽 = 100 Mb/s = **1 × 10⁸ b/s**
- 链路长度 = 1000 km = **1 × 10⁶ m**
- 传播速度 = **2 × 10⁸ m/s**

**第二步：算发送时延**

```
发送时延 = 8000 bit ÷ 1×10⁸ b/s = 8 × 10⁻⁵ s = 0.08 ms
```

**第三步：算传播时延**

```
传播时延 = 1×10⁶ m ÷ 2×10⁸ m/s = 5 × 10⁻³ s = 5 ms
```

**第四步：合计**

```
总时延 ≈ 0.08 ms + 5 ms = 5.08 ms
```

**这道题告诉我们什么？**

发送时延只有 0.08 ms，传播时延却高达 5 ms——**在这个场景下，传播时延占绝对主导**。这解释了为什么长距离通信（比如跨国）的性能瓶颈往往是距离，而不是带宽。

## 8. 六个常见误区

### 误区 1："带宽越大网速越快"

**部分错误。** 带宽只是影响**发送时延**。如果瓶颈在传播时延（长距离）或服务器响应速度，加大带宽毫无用处。跨国访问慢，加带宽是治不好的。

### 误区 2："OSI 七层是实际使用的模型"

**错误。** OSI 是理论参考模型。现实中真正跑的是 TCP/IP。说"某设备工作在四层"时，通常指的是 **TCP/IP 的传输层**，而不是 OSI 的第四层——虽然碰巧都是传输层，但语境不同。

### 误区 3："交换机是网络层设备"

**错误。** 普通二层交换机工作在**数据链路层**，只看 MAC 地址。**三层交换机**才是网络层设备。区分方法：看它是否做 IP 路由。

### 误区 4："应用层就是应用程序"

**错误。** 应用层是**协议**的集合（HTTP、DNS 等），不是软件的集合。Chrome 是应用程序，HTTP 才是应用层协议。

### 误区 5："100M 宽带下载速度就是 100MB/s"

**错误。** 100 Mbps = 100 ÷ 8 = **12.5 MB/s**。bit 和 Byte 差了 8 倍，这是最常见的坑。

### 误区 6："发送时延和传播时延是一回事"

**错误。**
- 发送时延看**数据量和带宽**（数据越多越慢）
- 传播时延看**距离和光速**（和带宽无关）
- 两者物理机制完全不同

## 9. 实践任务

理论看完必须动手。本阶段只有**一个**任务，但要认真做完。

### 任务：用 ping + Wireshark 观察封装过程

**准备工作**

1. 下载安装 [Wireshark](https://www.wireshark.org/)（免费）
2. 打开命令行（Windows：`Win + R` 输入 `cmd`）

**步骤**

**第 1 步：确定要抓的网卡**

```bash
# Windows
ipconfig
# 记下你正在使用的网卡的名称和 IP 地址

# Linux / macOS
ip addr
```

**第 2 步：启动抓包**

打开 Wireshark → 选择对应的网卡 → 双击开始抓包。

**第 3 步：产生流量**

在命令行执行：

```bash
ping www.baidu.com
```

**第 4 步：停止抓包并过滤**

在 Wireshark 的过滤栏输入：

```
icmp
```

按回车。你会看到一堆 ICMP 报文。

**第 5 步：逐层观察（重点）**

点击任意一个 ICMP 报文，看下方详情面板。**你会看到分层的树状结构**：

```
Frame 1: 98 bytes on wire (784 bits)        ← 物理层视角：多少比特
  └─ Ethernet II                            ← 数据链路层：源MAC、目的MAC
       └─ Internet Protocol Version 4        ← 网络层：源IP、目的IP、TTL
            └─ Internet Control Message      ← 应用层：ICMP 报文内容
```

**对照检查清单：**

- [ ] 找到 **Ethernet II** 这一行，记下源 MAC 和目的 MAC（目的 MAC 应该是你网关的 MAC）
- [ ] 找到 **Internet Protocol** 这一行，记下源 IP 和目的 IP
- [ ] 找到 **TTL** 字段，猜猜它代表什么（提示：每经过一个路由器减 1）
- [ ] 展开 ICMP 部分，找到 Type 和 Code 字段
- [ ] 观察请求包和应答包的**源/目的地址正好相反**

**第 6 步：思考题**

1. 为什么你看到的**目的 MAC 地址不是你 ping 的那台服务器的 MAC**？（提示：想想数据要先发给谁）
2. 一个 ping 包只有 98 字节，但里面真正有用的 ICMP 数据只有 32 字节，**剩下的 66 字节去哪了？**
3. 试着 `ping` 一个国外网站，对比 RTT。为什么带宽没变，时延却大了很多？

**进阶（可选）**

```bash
# 用 tracert 看数据包经过的每一跳
tracert www.baidu.com        # Windows
traceroute www.baidu.com     # Linux / macOS
```

观察每一跳的 IP 和时延，感受"数据包是怎么一站一站走的"。
