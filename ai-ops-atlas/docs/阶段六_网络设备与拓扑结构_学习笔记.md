## 1. 为什么单学协议还不够

### 1.1 从"看不见的规则"到"看得见的盒子"

前五阶段你学的都是**协议**——OSI 分层、TCP 握手、HTTP 报文……这些是"规则"，是**逻辑**层面的东西。

但真实世界里，规则要跑在**硬件设备**上：

```
   协议（逻辑）              设备（物理）
   ────────────             ────────────
   IP 路由规则      ←→       路由器 / 三层交换机
   MAC 转发规则     ←→       交换机 / 网桥
   以太网信号       ←→       网卡 / 集线器 / 中继器
   HTTP 报文        ←→       服务器 / 负载均衡器
```

> 💡 **术语解释｜网络设备（Network Device）**
> 网络中用于**连接、转发、控制、保护**数据的硬件装置。它根据自身**工作的 OSI 层次**，识别不同的数据单元（信号 / MAC 帧 / IP 包），执行不同的转发逻辑。
>
> **核心记忆**：**设备工作在哪一层，就"看得懂"那一层的数据。**

### 1.2 本阶段要建立的三个"图景"

学完本阶段，你应该能在脑子里建立三张图：

| 图景 | 回答什么问题 |
|---|---|
| **层次图** | 每种设备工作在 OSI 哪一层？识别什么？能隔离什么域？ |
| **拓扑图** | 一堆设备怎么连？星型 / 环型 / 网状各自适合什么场景？ |
| **组网图** | 一个真实的企业网络，从终端到互联网，中间经过哪些设备？ |

> 📌 **学习心法**：**不要把设备当成孤立的知识点记，而是"看到设备就想到它工作在几层、解决什么问题"。** 后面所有内容都是这个框架的展开。

## 2. 网络设备与工作层次总览

先看一张"总览表"，建立全局印象，后面再逐个拆解。

| 设备 | 工作层次 | 识别单元 | 核心功能 | 隔离冲突域 | 隔离广播域 |
|---|---|---|---|---|---|
| **网卡（NIC）** | 物理层 + 数据链路层 | 比特 / MAC 帧 | 让主机接入网络 | — | — |
| **中继器（Repeater）** | 物理层（L1） | 电/光信号 | 放大、整形、延长信号 | ❌ | ❌ |
| **集线器（Hub）** | 物理层（L1） | 电/光信号 | 多端口中继器，广播转发 | ❌ | ❌ |
| **调制解调器（Modem）** | 物理层（L1） | 电信号 | 数字↔模拟信号转换 | ❌ | ❌ |
| **网桥（Bridge）** | 数据链路层（L2） | MAC 帧 | 基于 MAC 转发，分割冲突域 | ✅ | ❌ |
| **二层交换机（Switch）** | 数据链路层（L2） | MAC 帧 | 多端口网桥，端口独立冲突域 | ✅ | ❌（可用 VLAN 划分） |
| **三层交换机（L3 Switch）** | 网络层（L3） | IP 包 | 高速路由 + 交换，硬件转发 | ✅ | ✅ |
| **路由器（Router）** | 网络层（L3） | IP 包 | 跨网段路由、NAT、隔离广播域 | ✅ | ✅ |
| **网关（Gateway）** | 应用层及以上 | 应用数据 | 协议转换，连接异构网络 | ✅ | ✅ |

> ⚠️ **最容易混淆的三组**（后面会逐个讲清）：
> 1. **集线器 vs 交换机**：前者"广播给所有人"，后者"只发给目标"
> 2. **二层交换机 vs 三层交换机**：前者只认 MAC，后者还能路由 IP
> 3. **三层交换机 vs 路由器**：功能重叠，但"主内"还是"主外"不同

> 💡 **术语解释｜数据单元（PDU，Protocol Data Unit）**
> 每一层处理的"数据包"有专门的叫法（阶段一学过，这里复习）：
>
> | 层次 | PDU 名称 | 通俗说法 |
> |---|---|---|
> | 物理层 | 比特（Bit） | 信号 |
> | 数据链路层 | 帧（Frame） | MAC 帧 |
> | 网络层 | 包（Packet） | IP 包 |
> | 传输层 | 段（Segment）/ 数据报（Datagram） | TCP 段 / UDP 数据报 |
> | 应用层 | 报文（Message） | 数据 |
>
> **设备"看懂的 PDU"决定了它的工作层次。**

## 3. 物理层设备：网卡、中继器、集线器

### 3.1 网卡（NIC）：每台设备的"网线插口"

> 💡 **术语解释｜网卡（NIC，Network Interface Card）**
> 计算机与网络之间的**接口硬件**。每块网卡都有一个**全球唯一的 MAC 地址**（阶段二学过）。
>
> **工作层次**：横跨**物理层和数据链路层**——物理层负责信号的收发（电气特性），数据链路层负责帧的封装与 MAC 地址处理。

**网卡的核心职责：**

| 职责 | 说明 |
|---|---|
| **信号的收发** | 把数据帧转成电/光信号发出去，把收到的信号还原成帧 |
| **MAC 地址** | 全球唯一，标识本机在局域网中的身份 |
| **帧的封装与解封** | 加上/去掉帧头帧尾 |
| **介质访问控制** | 如 CSMA/CD（半双工时代）、全双工控制 |
| **校验** | 计算/校验 FCS（帧校验序列），检测错误 |

> 📌 **现在很多设备（手机、笔记本）的网卡是"集成"或"无线"的**——比如 WiFi 模块也是一种网卡（无线网卡）。**有 MAC 地址的地方就有网卡。**

### 3.2 中继器（Repeater）：信号的"加油站"

**问题**：信号在网线/光纤里传输会**衰减**（衰减 = 信号变弱），传太远就认不出来了。

> 💡 **术语解释｜中继器（Repeater）**
> 最基础的**物理层**设备，作用是**把衰减的信号放大、整形后再转发**，从而**延长传输距离**。
>
> **关键词**：**只管信号，不认数据。** 它不识别 MAC 地址、IP 地址，收到什么就原样放大转发什么。

| 特性 | 说明 |
|---|---|
| 工作层次 | 物理层（L1） |
| 识别 | 电信号 / 光信号 |
| 功能 | 放大、整形、延长距离 |
| 缺点 | 不隔离冲突域/广播域，会把干扰信号也一起放大 |
| 限制 | 以太网 **5-4-3 规则**：最多 5 段线、4 个中继器、3 个网段可接设备 |
| 现状 | 已基本被交换机取代 |

> 💡 **术语解释｜5-4-3 规则**
> 早期以太网（共享式）的组网限制：**最多 5 个网段、最多 4 个中继器、最多 3 个网段可以连接设备**。原因是信号经过多次中继后，往返时延（RTT）会超过争用期（51.2μs，阶段二学过），CSMA/CD 就会失效。

### 3.3 集线器（Hub）：共享总线的"大喇叭"

> 💡 **术语解释｜集线器（Hub，集线器）**
> **本质是"多端口中继器"**，工作在**物理层**。所有端口**共享同一条总线**。
>
> **核心行为**：**任意端口收到的数据，会广播给所有其他端口。**

**集线器的工作方式（对比交换机）：**

```
集线器（Hub）—— 广播式：
   端口1 收到数据
        │
        ├──▶ 端口2  （不管你需不需要）
        ├──▶ 端口3  （不管你需不需要）
        ├──▶ 端口4  （不管你需不需要）
        └──▶ ...

交换机（Switch）—— 定向式：
   端口1 收到数据（目标是端口3 的 MAC）
        │
        └──▶ 端口3  （只发给目标端口）
```

**集线器的致命问题：**

| 问题 | 后果 |
|---|---|
| **所有端口同一冲突域** | 两台设备同时发数据就"撞车"（冲突），必须重发 |
| **带宽全网共享** | 10 台设备共享 100Mbps，每台平均只有 10Mbps |
| **半双工** | 同一时间只能收或发，不能同时 |
| **无数据筛选** | 广播转发，安全性差（任何人能抓到别人的数据） |
| **无学习能力** | 不知道谁在哪个端口 |

> ⚠️ **为什么集线器被淘汰？** 因为它**共享冲突域 + 半双工 + 广播转发**，效率极低。交换机**每端口独立冲突域 + 全双工 + 定向转发**，全面碾压。**现在家庭、企业里几乎见不到集线器了。**

> 📌 **一句话记忆**：
> - **中继器** = 1 个口，只放大信号
> - **集线器** = 多个口，放大 + 广播（"大喇叭"）
> - **交换机** = 多个口，智能定向转发（"分机接线员"）

### 3.4 调制解调器（Modem）：数字与模拟的翻译官

> 💡 **术语解释｜调制解调器（Modem，俗称"猫"）**
> **调制（Modulation）**：把数字信号转成模拟信号（发出去）。
> **解调（Demodulation）**：把模拟信号还原成数字信号（收进来）。
>
> **用途**：让数字设备（电脑）能通过模拟线路（电话线、同轴电缆）传输数据。

| 类型 | 说明 |
|---|---|
| **ADSL Modem** | 走电话线，现代已少用 |
| **光猫（ONU）** | 光纤入户的"光猫"，把光信号转成电信号（**现在家庭最主流**） |
| **Cable Modem** | 走有线电视同轴电缆 |

> 📌 **家里的"光猫"其实就是一种 Modem**（更准确地说是 **ONU**，光网络单元）。它负责把运营商的光信号转成你路由器能用的以太网信号，**是家庭宽带的第一跳设备**。

## 4. 数据链路层设备：网桥与交换机

### 4.1 网桥（Bridge）：冲突域的"分界墙"

**问题**：集线器把所有人都塞进一个冲突域，人一多就"撞车"。

> 💡 **术语解释｜网桥（Bridge）**
> **数据链路层（L2）**设备，能**解析 MAC 帧、识别 MAC 地址**，基于 MAC 地址**定向转发**数据。核心作用是**分割冲突域**。
>
> **本质**：一个"只有 2 个口的智能设备"，把网络分成两段，两段的冲突互相隔离。

**网桥如何工作（自学习，阶段二学过）：**

```
① 学习：记录"源 MAC ← 哪个端口来"→ 建立 MAC-端口 映射表
② 转发：查表，知道目标在哪个端口就只往那发
③ 泛洪：查不到目标 → 广播给所有端口（除来源口）
④ 过滤：目标就在来源端口 → 丢弃（不用转发）
```

| 特性 | 说明 |
|---|---|
| 工作层次 | 数据链路层（L2） |
| 识别 | MAC 帧、MAC 地址 |
| 隔离冲突域 | ✅（每个端口独立） |
| 隔离广播域 | ❌（广播帧照转发） |
| 端口数 | 少（通常 2 个） |
| 现状 | 已被交换机取代（交换机就是"多口网桥"） |

### 4.2 二层交换机（Switch）：内网的核心接入设备

> 💡 **术语解释｜交换机（Switch）**
> **多端口、硬件加速的网桥**。工作在**数据链路层**，基于 **MAC 地址**转发数据帧。
>
> **核心特征**：**每个端口都是独立的冲突域**，端口之间互不干扰。

**交换机的三大核心功能（阶段二详讲过，这里复习）：**

| 功能 | 说明 |
|---|---|
| **地址学习** | 记录源 MAC 与端口的关系，建立 **MAC 地址表** |
| **帧转发/过滤** | 查表定向转发，同端口丢弃 |
| **泛洪（Flooding）** | 查不到目标 / 广播帧 / 组播帧 → 发往所有其他端口 |

**交换机相比集线器的优势：**

| 对比项 | 集线器 | 交换机 |
|---|---|---|
| 工作层次 | L1 | L2 |
| 冲突域 | 全网 1 个 | **每端口 1 个** |
| 双工模式 | 半双工 | **全双工** |
| 带宽 | 全网共享 | **每端口独享** |
| 转发方式 | 广播 | **定向单播** |
| 数据安全 | 差（都能抓到） | 好（只发给目标） |
| 地址学习 | 无 | **有** |

**交换机的三种交换模式：**

| 模式 | 原理 | 延迟 | 可靠性 |
|---|---|---|---|
| **存储转发（Store-and-Forward）** | 收完整帧、校验 FCS 后再转发 | 高 | **最可靠**（可丢弃错误帧） |
| **直通（Cut-Through）** | 读到目的 MAC 就立即转发 | **最低** | 低（错误帧也转发） |
| **无碎片（Fragment-Free）** | 读前 64 字节（最小帧长）后转发 | 中 | 中（可过滤碰撞碎片） |

> 💡 **术语解释｜MAC 地址表（MAC Address Table / CAM 表）**
> 交换机内部的一张表，记录"**MAC 地址 → 端口**"的映射。靠**源 MAC 学习**建立，靠它实现**定向转发**。
>
> **交换机对未知单播帧的处理**：泛洪（发往所有端口，除来源口）——所以交换机**不隔离广播域**。

> ⚠️ **二层交换机的局限**：**普通二层交换机没有 IP 路由能力**，无法让**不同 IP 网段**的设备互通。要跨网段，必须靠**路由器或三层交换机**（下面讲）。

### 4.3 VLAN：给二层交换机"逻辑分区"

虽然阶段二已讲过 VLAN，但它是"设备与组网"里绕不开的一环，这里简要回顾它如何改变交换机的行为：

> 💡 **术语解释｜VLAN（Virtual LAN，虚拟局域网）**
> 在**一台物理交换机**上，用软件划分出**多个逻辑上独立的局域网**。**同一 VLAN 内可以二层互通，不同 VLAN 之间必须经过三层设备（路由器/三层交换机）。**
>
> **核心价值**：**把一个大的广播域，切分成多个小的广播域** → 减少广播风暴、提升安全、便于管理。

```
物理上：一台 24 口交换机
逻辑上：
   VLAN 10（财务部）：端口 1-8
   VLAN 20（研发部）：端口 9-16
   VLAN 30（访客）：  端口 17-24
        │
        └── 不同 VLAN 之间默认不能通信，需经过三层设备
```

> 📌 **交换机 + VLAN = 二层网络的基本盘。** 一个企业内网，几乎一定是"多个 VLAN + 三层设备互联"的结构。

## 5. 网络层设备：路由器与三层交换机

### 5.1 路由器（Router）：跨网段的"交通枢纽"

> 💡 **术语解释｜路由器（Router）**
> **网络层（L3）**设备，基于 **IP 地址**，在**不同网络之间**转发数据包。它是**连接内网与外网、连接不同网段的核心关口**。

**路由器的核心功能：**

| 功能 | 说明 |
|---|---|
| **路由选择** | 查**路由表**，根据目的 IP 找到下一跳 |
| **跨网段转发** | 连接不同 IP 网段，让它们互通 |
| **隔离广播域** | **每个接口是一个独立广播域**（天然阻断广播） |
| **NAT 地址转换** | 让内网私有 IP 共享一个公网 IP 上网（阶段三学过） |
| **DHCP 服务** | 给内网设备分配 IP |
| **访问控制 / 防火墙** | ACL、包过滤 |
| **VPN 拨号** | 建立加密隧道 |

**路由器 vs 交换机（核心对比）：**

| 对比项 | 交换机 | 路由器 |
|---|---|---|
| 工作层次 | L2（二层交换机） | L3 |
| 转发依据 | **MAC 地址** | **IP 地址** |
| 作用范围 | **同一网段内** | **不同网段之间** |
| 隔离冲突域 | ✅ | ✅ |
| 隔离广播域 | ❌（除非用 VLAN） | **✅ 天然隔离** |
| 转发速度 | **快**（硬件芯片） | **相对慢**（需查路由、改 MAC、改 TTL） |
| 主要场景 | 内网接入 | 网络出口、跨网互联 |

> 📌 **一句话记忆**：
> **交换机是"楼里的电梯"（同一栋楼内找人），路由器是"城市间的航班"（跨城市找人）。**

> ⚠️ **常见误区**：很多人以为"路由器比交换机高级，所以更快"。**恰恰相反**——在**同一网段内**，交换机转发**远快于**路由器，因为交换机是**硬件直转**，路由器要**查表、改包、重算校验和**。所以内网都用交换机，路由器只在**必须跨网段**时才用。

### 5.2 三层交换机（L3 Switch）：会路由的交换机

**问题**：企业内网有几十个 VLAN，如果 VLAN 之间通信都走路由器，路由器会成为瓶颈（软件转发慢）。

**答案**：**三层交换机。**

> 💡 **术语解释｜三层交换机（Layer 3 Switch）**
> **兼具二层交换的高速转发能力和三层路由功能**的设备。它在硬件芯片（ASIC）里实现路由转发，**速度接近二层交换，但能做跨网段路由**。
>
> **本质**：**"交换机 + 路由功能"**，一次路由、多次交换（第一个包走路由确定路径，后续包直接硬件转发）。

**为什么需要它？（VLAN 间通信场景）**

```
    传统方案（单臂路由 / 外部路由器）：
       VLAN10 ─┐
       VLAN20 ─┼─▶ 路由器（软件转发，慢）─▶ 回交换机
       VLAN30 ─┘         ↑ 瓶颈

    三层交换机方案：
       VLAN10 ─┐
       VLAN20 ─┼─▶ 三层交换机（硬件路由，快）
       VLAN30 ─┘    · 配置 SVI（每个 VLAN 一个虚拟接口）
                    · 内部硬件直转，无外部瓶颈
```

> 💡 **术语解释｜SVI（Switch Virtual Interface，交换机虚拟接口）**
> 三层交换机上为**每个 VLAN 创建的虚拟三层接口**，作为该 VLAN 的**网关**。例如 VLAN 10 的 SVI 是 `interface Vlanif 10`，配个 IP 地址当网关，就能实现 VLAN 间路由。

**三层交换机 vs 路由器：**

| 对比项 | 三层交换机 | 路由器 |
|---|---|---|
| 主要定位 | **内网**（园区网核心/汇聚） | **网络边界**（内网↔外网） |
| 转发性能 | **极高**（硬件 ASIC） | 高但相对较低（软件为主） |
| 端口密度 | **高**（几十上百个以太网口） | 低（通常几个到十几个口） |
| 接口类型 | 以太网为主 | **丰富**（串口、光口、E1、POS 等） |
| 功能侧重 | 高速转发 + 简单路由 | **复杂功能**（NAT、VPN、QoS、ACL、广域网协议） |
| 典型场景 | 园区网汇聚/核心、数据中心 | 出口网关、运营商、广域网 |

> 📌 **记忆口诀**：
> - **"对内用三层交换机，对外用路由器"**
> - 三层交换机 = "内网的高速立交桥"，路由器 = "连接外部的收费站"

### 5.3 网关（Gateway）：协议转换的"翻译官"

> 💡 **术语解释｜网关（Gateway）**
> 最广义的"网络关口"。**狭义**指"协议转换设备"——连接**两个使用不同协议**的网络，做**协议翻译**。
>
> **工作层次**：**应用层及以上**（要理解应用协议才能翻译）。

**两类"网关"要区分：**

| 类型 | 含义 | 例子 |
|---|---|---|
| **默认网关（Default Gateway）** | 主机配置里的"出口 IP"，其实就是**路由器的接口地址** | 你电脑设置里的 `192.168.1.1` |
| **协议网关（Protocol Gateway）** | 转换不同协议栈的设备 | 邮件网关、VoIP 网关、IoT 网关、API 网关 |

> ⚠️ **考试高频陷阱**："默认网关"是**配置项**（指向路由器），"网关设备"是**一类设备**（做协议转换）。**两者不是一回事**，别混淆。

> 💡 **术语解释｜API 网关（API Gateway）**
> 微服务架构中的"统一入口"，负责**路由转发、认证鉴权、限流熔断、协议转换**（如把 HTTP 转成 gRPC）。**现代软件架构里的"网关"多指这个。**

## 6. 冲突域与广播域

这两个概念是**设备与组网的"分水岭"**，必须彻底搞清。

> 💡 **术语解释｜冲突域（Collision Domain）**
> **同一时间只允许一台设备发送数据**的范围。多台同时发送会**"碰撞"（冲突）**，导致数据损坏、需要重传。
>
> **产生原因**：共享介质（集线器、总线）导致的竞争。

> 💡 **术语解释｜广播域（Broadcast Domain）**
> **广播帧能够传播到的所有设备**的范围。广播域过大会引发**广播风暴**，占用大量带宽、拖垮网络。

**哪些设备隔离什么域（必背表）：**

| 设备 | 隔离冲突域？ | 隔离广播域？ |
|---|---|---|
| 中继器 / 集线器（L1） | ❌ | ❌ |
| 网桥 / 二层交换机（L2） | ✅（每端口一个） | ❌（整机一个，**可用 VLAN 划分**） |
| 路由器 / 三层交换机（L3） | ✅ | ✅（**每接口一个**） |

> 📌 **一句话记忆**：
> - **隔离冲突域靠"二层"**（交换机每端口独立冲突域）
> - **隔离广播域靠"三层"**（路由器/三层交换机每接口独立广播域）或 **VLAN**

**图示理解：**

```
                    ┌───────────────┐
                    │   路由器       │  ← 路由器每个接口 = 一个独立广播域
                    └───┬───────┬───┘
            广播域A     │       │     广播域B
              ┌─────────┘       └─────────┐
         ┌────┴────┐                 ┌────┴────┐
         │ 交换机   │                 │ 交换机   │
         └─┬─┬─┬─┬─┘                 └─┬─┬─┬─┬─┘
           │ │ │ │                     │ │ │ │
        冲突域×4（每端口一个）        冲突域×4
```

> ⚠️ **广播风暴（Broadcast Storm）**：当网络存在**二层环路**且没有 STP 时，广播帧会在环里无限循环、不断复制，瞬间耗尽带宽，网络瘫痪。**这是"隔离广播域"和"部署 STP"的根本原因。**

## 7. 安全与优化设备

前面讲的是"转发"设备，这里讲**"保护"和"加速"**的设备。

### 7.1 防火墙（Firewall）：网络的"门禁"

> 💡 **术语解释｜防火墙（Firewall）**
> 部署在**网络边界**，根据**预设的安全规则**，**允许或拒绝**流量的设备。它是"内网与外网之间的关卡"。

**防火墙的四代演进：**

| 代际 | 类型 | 检查什么 | 特点 |
|---|---|---|---|
| 第一代 | **包过滤防火墙** | IP 地址、端口、协议 | 快，但只看"信封"，不看内容 |
| 第二代 | **状态检测防火墙** | 连接状态表（会话） | 记住"谁先发起的连接"，更安全 |
| 第三代 | **应用层防火墙（代理型）** | 应用层数据（HTTP/FTP） | 深入内容，但慢 |
| 第四代 | **下一代防火墙（NGFW）** | 应用识别 + 用户 + 内容 + 威胁 | 集成 IPS、防病毒、威胁情报 |

> 💡 **术语解释｜状态检测（Stateful Inspection）**
> 防火墙维护一张**连接状态表**，记录每条连接的**协议、源/目的 IP、端口、状态**。
>
> **关键能力**：**"只放行内部主动发起的连接的回包"**。比如你在内网访问网页，返回的数据包能通过（因为它属于"已建立的连接"）；但外网主动发起的连接会被拦（不在状态表里）。这比"只看包内容"的包过滤**安全得多**。

> 💡 **术语解释｜下一代防火墙（NGFW，Next-Generation Firewall）**
> Gartner 提出的概念。在传统防火墙基础上，**深度集成**：
> - **应用识别与控制**（能识别"这是微信还是迅雷"，不只是看端口）
> - **入侵防御（IPS）**
> - **用户身份管理**（按人/组而非仅 IP 放行）
> - **加密流量检查**
> - **威胁情报集成**
>
> **本质**：从"看门牌"升级到"看人 + 看行李 + 看行为"。

**防火墙的部署模式：**

| 模式 | 说明 |
|---|---|
| **网关模式（路由模式）** | 防火墙作为网关，串在网络出口，**最常见** |
| **透明模式（网桥模式）** | 像一段"透明网线"串进去，不改 IP，**旁路部署方便** |
| **旁路模式** | 只监听不阻断，用于检测（IDS 常见） |

> 📌 **易混淆的三种"安全设备"**：
> - **防火墙**：**控制"能不能通"**（访问控制）
> - **IDS（入侵检测系统）**：**只检测、告警**，不阻断（旁路）
> - **IPS（入侵防御系统）**：**检测并阻断**（串联在线路上）

### 7.2 负载均衡器（Load Balancer）：流量的"分发员"

> 💡 **术语解释｜负载均衡（Load Balancing）**
> 把大量请求**分发到多台后端服务器**，避免单台过载，同时提供**故障转移**（某台挂了就不发给它）。

**四层 vs 七层负载均衡（核心考点）：**

| 对比项 | 四层（L4） | 七层（L7） |
|---|---|---|
| 工作层次 | 传输层 | 应用层 |
| 看什么 | **IP + 端口**（TCP/UDP） | **HTTP 内容**（URL、Header、Cookie） |
| 能做的判断 | "这个连接给哪台服务器" | "这个 `/api` 请求给哪台，`/img` 请求给哪台" |
| 性能 | **高**（只改 IP，不改内容） | 相对低（要解析应用层） |
| 典型代表 | **LVS、F5** | **Nginx、HAProxy、云 ALB** |
| SSL 卸载 | 一般不做 | **可以**（解密 HTTPS 后按内容分发） |

> 💡 **术语解释｜SSL 卸载（SSL Offloading）**
> 把 **HTTPS 解密**的工作从后端服务器**转移到负载均衡器**上做。负载均衡器解密后，用明文 HTTP 转发给后端，**减轻后端 CPU 压力**。

**常见负载均衡算法：**

| 算法 | 原理 | 特点 |
|---|---|---|
| **轮询（Round Robin）** | 按顺序轮流分发 | 简单，适合服务器性能相近 |
| **加权轮询（Weighted RR）** | 按权重分配（性能强的多分） | 适合服务器配置不同 |
| **最少连接（Least Connections）** | 发给当前连接数最少的 | 适合长连接、请求耗时差异大 |
| **IP 哈希（IP Hash）** | 同一 IP 固定发给同一台 | 实现**会话保持**（但某台挂了会乱） |
| **一致性哈希（Consistent Hashing）** | 哈希环，节点增减影响最小 | 适合缓存集群，减少缓存失效 |

> 💡 **术语解释｜会话保持（Session Persistence / Sticky Session）**
> 让**同一用户的多次请求固定落到同一台后端服务器**。因为用户登录状态可能只存在某台服务器的 Session 里（阶段五学过）。**常用 IP 哈希或 Cookie 实现。**

> 📌 **负载均衡器的价值**：
> 1. **分摊压力**（横向扩展）
> 2. **故障转移**（健康检查，自动剔除故障机）
> 3. **SSL 卸载**（集中解密）
> 4. **灰度发布**（按比例导流到新版本）

> 💡 **术语解释｜健康检查（Health Check）**
> 负载均衡器**定期探测后端服务器**（如发 HTTP 请求或 TCP 探测），发现不健康就**自动停止分发**，恢复后再自动加回。**这是"高可用"的关键机制。**

### 7.3 代理服务器（Proxy）：站在中间的"中间人"

> 💡 **术语解释｜代理服务器（Proxy Server）**
> 代表客户端或服务器**转发请求**的中间设备。它**"代理"某一方去和另一方通信**。

**正向代理 vs 反向代理（高频考点）：**

| 对比项 | 正向代理（Forward Proxy） | 反向代理（Reverse Proxy） |
|---|---|---|
| 代理谁 | **代理客户端** | **代理服务器** |
| 谁知道谁 | 服务器**不知道**真实客户端（只看到代理） | 客户端**不知道**真实服务器（只看到代理） |
| 典型用途 | 科学上网、企业统一出口、访问控制 | 负载均衡、SSL 卸载、缓存、WAF |
| 部署位置 | 靠近**客户端** | 靠近**服务器** |
| 例子 | 浏览器代理、VPN | Nginx、CDN |

**一句话记忆：**
- **正向代理**："我（客户端）找人**替我去**拿东西"——服务器只知道代理，不知道我
- **反向代理**："你（客户端）以为在跟我说话，其实我**只是个前台**，真正的老板在后面"——客户端只知道代理，不知道真实服务器

```
正向代理：                          反向代理：
 客户端 ──▶ 正向代理 ──▶ 服务器       客户端 ──▶ 反向代理 ──▶ 多台服务器
 （代理客户端身份）                   （代理服务器身份，做负载均衡）
```

> 📌 **Nginx 是典型的"反向代理 + 七层负载均衡 + SSL 卸载 + 缓存 + WAF"综合体**，是现代 Web 架构的标配组件。

### 7.4 其他安全设备速览

| 设备 | 作用 |
|---|---|
| **IDS** | 入侵检测系统，旁路监听，**只告警不阻断** |
| **IPS** | 入侵防御系统，串联在线，**检测并阻断** |
| **WAF** | Web 应用防火墙，专门防 SQL 注入、XSS 等 Web 攻击 |
| **堡垒机** | 运维审计，所有运维操作经它跳转并录屏 |
| **网闸（GAP）** | 物理隔离不同安全域（如内网与外网物理断开） |
| **VPN 网关** | 建立加密隧道，实现远程安全接入 |
| **上网行为管理** | 流量审计、应用管控、行为记录 |

> ⚠️ **防火墙 vs WAF vs IPS 的区别**：
> - **防火墙**：管"**能不能进**"（端口/IP 层面）
> - **WAF**：管"**进来的 Web 请求正不正常**"（应用层，防注入/XSS）
> - **IPS**：管"**流量里有没有攻击特征**"（全流量，含漏洞利用）

## 8. 无线网络设备

### 8.1 AP 与 AC：无线网络的两大件

> 💡 **术语解释｜AP（Access Point，无线接入点）**
> 把**有线网络转换成无线信号**的设备，让手机、笔记本等无线终端接入。**"无线交换机"**。

> 💡 **术语解释｜AC（Access Controller，无线控制器）**
> **集中管理多个 AP** 的设备，负责统一下发配置、认证、漫游、射频调优、负载均衡。

### 8.2 胖 AP vs 瘦 AP

| 对比项 | 胖 AP（Fat AP） | 瘦 AP（Fit AP） |
|---|---|---|
| 功能 | **集成了全部功能**（认证、DHCP、路由、加密） | **只负责无线信号收发**，其他交给 AC |
| 能否独立工作 | **能**（自带"大脑"） | **不能**（必须有 AC） |
| 管理方式 | 逐台配置，**难管理** | AC 统一下发，**易管理** |
| 适用规模 | **小**（家庭、小店，几台 AP） | **大**（企业、校园，几十上百台 AP） |
| 类比 | 每家自己挖井取水 | 自来水厂统一供水（AC 是水厂） |

> 💡 **术语解释｜CAPWAP（Control And Provisioning of Wireless Access Points）**
> 瘦 AP 与 AC 之间的**通信协议**，负责**下发配置、上报状态、转发数据**。瘦 AP 上线时会自动通过 CAPWAP 找到 AC 并获取配置。

> 📌 **家庭无线路由器 = "胖 AP + 路由器 + 交换机 + DHCP 服务器"的合体**。企业里则用"AC + 多个瘦 AP"的架构，才能实现**无缝漫游**和**统一管理**。

> 💡 **术语解释｜漫游（Roaming）**
> 无线终端从一个 AP 的覆盖范围移动到另一个 AP 时，**保持网络连接不中断**。瘦 AP + AC 架构下，AC 统一管理，漫游体验好（切换快、不掉线）。

> 💡 **术语解释｜BSSID 与 SSID**
> - **SSID**：你看到的**无线网络名字**（如 "Office-WiFi"），是"逻辑名"
> - **BSSID**：**每个 AP 射频的 MAC 地址**，是"物理标识"
>
> **同一个 SSID 可以对应多个 BSSID**（多个 AP 广播同一个名字，实现漫游）。

### 8.3 无线组网拓扑

```
      AC（无线控制器）
       │
       ├──────────┬──────────┐
       │          │          │
     AP1        AP2        AP3      ← 瘦 AP 通过有线接入交换机
       │          │          │
     📱📱       💻💻       📱📱      ← 无线终端

   数据流：终端 → AP → 交换机 → AC/网关 → 外网
```

> 📌 **企业无线三件套**：**AC + 瘦 AP + PoE 交换机**（PoE = 网线同时供电，省去每个 AP 单独拉电源）。

> 💡 **术语解释｜PoE（Power over Ethernet，以太网供电）**
> 通过**一根网线同时传输数据和电力**。AP、IP 摄像头、IP 电话等设备**不用单独接电源**，一根网线搞定。**企业无线部署的标配。**

## 9. 网络拓扑结构

> 💡 **术语解释｜拓扑结构（Topology）**
> 网络中**设备的物理或逻辑连接方式**。它决定了网络的**可靠性、成本、扩展性、故障影响范围**。

### 9.1 六种基本拓扑

**① 总线型（Bus）**

```
   ┌───┬───┬───┬───┬───┐
   │   │   │   │   │   │   ← 所有设备挂在同一条总线上
  PC1 PC2 PC3 PC4 PC5
```

| 优点 | 缺点 |
|---|---|
| 成本低、布线简单、线缆少 | **主干故障 → 全网瘫痪** |
| 适合小型网络 | **数据冲突多**（共享总线） |
| | 故障难定位 |

**② 星型（Star）**

```
        PC1
         │
   PC2 ──┼── PC3     ← 所有设备连到中心节点
         │
        PC4
         │
    [中心设备：交换机]
```

| 优点 | 缺点 |
|---|---|
| **易安装维护** | **中心节点故障 → 全网瘫痪**（单点故障） |
| **单节点故障不影响全网** | 布线成本较高（每台设备都要连到中心） |
| 故障易定位 | 中心设备压力大 |

> 📌 **现代局域网几乎都是星型（物理上）**——所有设备连到交换机。**这是最常见的拓扑。**

**③ 环型（Ring）**

```
    PC1 ──▶ PC2
     ▲        │
     │        ▼
    PC4 ◀── PC3     ← 设备首尾相连成环，数据单向传递
```

| 优点 | 缺点 |
|---|---|
| **无数据冲突**（令牌传递控制） | **单点故障 → 全网中断**（除非双环） |
| 传输效率高、延迟可预测 | **扩展性差**（加节点要断环） |
| 适合令牌环网 | 现代已少用 |

**④ 树型（Tree）**

```
         [核心]
        /      \
    [汇聚1]   [汇聚2]     ← 分层结构，星型的组合
    /   \      /   \
  [接入][接入][接入][接入]
```

| 优点 | 缺点 |
|---|---|
| **易扩展**（加分支方便） | **高层节点故障 → 影响下层** |
| **故障隔离**（一个分支挂了不影响其他分支） | 根节点是单点 |
| 适合**大型分层网络** | 布线复杂 |

> 📌 **树型 = "星型的嵌套"，就是第 10 章要讲的"三层网络架构"的拓扑形态。**

**⑤ 网状（Mesh）**

```
     A ────── B
     │ \    / │
     │   \/   │      ← 节点之间多条路径互联
     │   /\   │
     C ────── D
```

| 优点 | 缺点 |
|---|---|
| **冗余高、可靠性极强** | **布线复杂、成本高** |
| 多条路径，一条断了走另一条 | **维护困难** |
| 适合**核心骨干、广域网** | 端口消耗大（N 个节点要 N-1 条线） |

> 💡 **术语解释｜全互联（Full Mesh）vs 部分互联（Partial Mesh）**
> - **全互联**：每两个节点之间都直连（N 个节点需要 N(N-1)/2 条链路）——**成本极高，只用于极少数核心**
> - **部分互联**：关键节点之间多条路径，非关键节点单连——**性价比之选**
>
> **广域网核心、数据中心骨干**常用网状（或部分网状）。

**⑥ 混合型（Hybrid）**

实际网络**几乎都是混合型**——比如"核心层网状 + 接入层星型"。**它是多种拓扑的组合。**

### 9.2 六种拓扑对比总表

| 拓扑 | 成本 | 可靠性 | 扩展性 | 故障影响 | 典型场景 |
|---|---|---|---|---|---|
| **总线型** | 低 | 低 | 差 | 主干断→全网瘫 | 早期小型网 |
| **星型** | 中 | 中 | 好 | 中心断→全网瘫 | **现代局域网** |
| **环型** | 中 | 中 | 差 | 单点断→全网瘫 | 令牌环网（历史） |
| **树型** | 中高 | 中高 | **好** | 上层断→影响下层 | **企业分层网** |
| **网状** | **高** | **极高** | 中 | 影响小 | **广域网骨干** |
| **混合型** | 视组合 | 高 | 好 | 视设计 | **几乎所有真实网络** |

> 📌 **选择原则**：
> - **终端接入** → 星型（连到交换机）
> - **企业分层** → 树型（接入/汇聚/核心）
> - **核心骨干/广域** → 网状（冗余）
> - **真实网络** → 混合型（组合使用）

## 10. 层次化组网：接入 / 汇聚 / 核心

> 💡 **术语解释｜三层网络架构（Three-Tier Architecture）**
> 把网络按功能分成**接入层、汇聚层、核心层**三层的**模块化设计**。是**园区网、校园网、企业内网**的经典架构。

### 10.1 三层各自的职责

| 层次 | 职责 | 典型设备 | 关键点 |
|---|---|---|---|
| **核心层（Core）** | **高速骨干转发** | 高性能三层交换机 | **只做高速转发，不做复杂策略** |
| **汇聚层（Aggregation）** | **收敛流量、策略控制、网关** | 三层交换机 | **ACL、路由、安全策略、VLAN 网关下沉于此** |
| **接入层（Access）** | **终端接入** | 二层交换机、AP | **端口安全、802.1X 认证、MAC 过滤** |

```
                    ┌─────────────┐
                    │   核心层     │  高速转发，冗余设计
                    │  (Core)     │  不做复杂策略
                    └──┬───────┬──┘
              ┌────────┘       └────────┐
        ┌─────┴─────┐            ┌─────┴─────┐
        │  汇聚层    │            │  汇聚层    │  VLAN 网关、ACL、路由
        │(Aggregation)│          │(Aggregation)│
        └──┬─────┬───┘            └───┬─────┬──┘
     ┌─────┘     └─────┐        ┌─────┘     └─────┐
  ┌──┴──┐        ┌─────┴──┐  ┌──┴──┐        ┌─────┴──┐
  │接入层│        │ 接入层  │  │接入层│        │ 接入层  │  终端接入
  │(Access)│      │(Access)│  │(Access)│      │(Access)│
  └──┬──┘        └────────┘  └─────┘        └────────┘
     │
  PC/AP/摄像头
```

### 10.2 为什么核心层"不做复杂策略"

> ⚠️ **核心层的设计原则：简单、快、稳。**
>
> 因为核心层承载**全网流量**，一旦在这里做复杂的 ACL、NAT、策略过滤，会**消耗大量 CPU、拖慢转发、增加故障点**。所以：
> - **核心层只做"高速转发"**（越简单越快）
> - **复杂策略下沉到汇聚层**（ACL、路由、安全策略都在这里做）
> - **终端控制放在接入层**（端口安全、认证）

> 📌 **一句话记忆**：**"核心只管快，汇聚管策略，接入管终端。"**

### 10.3 三层架构的优势

| 优势 | 说明 |
|---|---|
| **模块化** | 局部改动不影响全网，扩容灵活 |
| **分层管理** | 每层职责清晰，可分层选配设备，节约成本 |
| **网关下沉** | VLAN 网关在汇聚层，核心负载低 |
| **故障隔离** | 一层出问题不会立刻影响其他层 |

> ⚠️ **三层架构的缺点**：
> - 层级多、**链路复杂，易产生二层环路**（要靠 STP/MSTP 防环）
> - 策略分散在多台设备，**排查和维护工作量大**
> - 对运维人员技术要求高

### 10.4 现代演进：大二层与 VXLAN

**① 园区网大二层（扁平化）**

设计思路：**"重核心、轻接入"**——把网关和策略**上收到高性能核心**，接入/汇聚只做简单转发，用低端设备即可。

- **优点**：层级少、延迟低、部署简单
- **缺点**：压力集中在核心，核心故障影响全网

**② 数据中心大二层（VXLAN）**

> 💡 **术语解释｜VXLAN（Virtual Extensible LAN）**
> 用**隧道技术**（在 IP 网络上封装二层帧）构建**跨物理机房的大二层网络**。解决传统 VLAN 的**数量限制（4096 个）**和**跨机房二层不通**的问题。

**为什么云数据中心需要它？**

- 虚拟机**在线热迁移**要求迁移前后 **IP、MAC、VLAN 不变** → 需要**大范围二层网络**
- 传统 STP **收敛慢、带宽利用率低**，撑不起大规模虚拟化
- **VXLAN** 突破了 VLAN 数量限制，隔离广播，支撑虚拟机跨机房迁移

> 📌 **架构演进总结**：
> - **传统三层架构**：终端固定、无虚拟化的园区网
> - **园区大二层**：终端密集、追求轻量化接入
> - **数据中心 VXLAN**：虚拟化云平台、跨机房热迁移

## 11. 冗余与高可用

**网络最怕什么？单点故障。** 冗余就是"关键环节都准备备份"，高可用就是"故障时业务不中断"。

### 11.1 冗余的层次

| 冗余类型 | 说明 | 技术手段 |
|---|---|---|
| **设备冗余** | 关键设备有备份 | 双机热备、堆叠 |
| **链路冗余** | 关键链路有多条 | 链路聚合、双上行 |
| **网关冗余** | 网关有备份 | VRRP / HSRP |
| **电源/风扇冗余** | 硬件部件有备份 | 冗余电源、冗余风扇 |
| **路径冗余** | 网络有多条路径 | 网状拓扑、STP/MSTP |

### 11.2 链路聚合（Link Aggregation）

> 💡 **术语解释｜链路聚合（Link Aggregation / EtherChannel / Bonding）**
> 把**多条物理链路捆绑成一条逻辑链路**，实现**带宽叠加**和**链路冗余**。

```
        两台交换机之间
    ┌───────────────────────┐
    │  ┌───物理链路1───┐     │
交换机A ─┼───物理链路2───┼─ 交换机B
    │  └───物理链路3───┘     │
    └───────────────────────┘
          ↑ 3 条链路捆绑成 1 条逻辑链路
          · 带宽 = 3 条之和
          · 断 1 条不影响，自动切到其他
```

| 优势 | 说明 |
|---|---|
| **增加带宽** | 多条链路带宽叠加（如 3×1G = 3G） |
| **提高可靠性** | 一条断了自动切换，无缝故障转移 |
| **避免环路** | 聚合后是一条逻辑链路，不会形成二层环路 |

> 💡 **术语解释｜LACP（Link Aggregation Control Protocol）**
> 链路聚合的**标准协议**（IEEE 802.3ad），用于**自动协商**聚合成员、**检测链路故障**。华为叫 **Eth-Trunk**，思科叫 **EtherChannel**，Linux 叫 **Bonding**。

> ⚠️ **注意**：链路聚合是**逻辑上的一条链路**，**单个数据流的带宽不会超过单条物理链路**（因为同一个流的包还是走同一条线）。它提升的是**总吞吐量**和**可靠性**，不是单流速度。

### 11.3 堆叠（Stacking）

> 💡 **术语解释｜堆叠（Stacking）**
> 把**多台物理交换机通过专用线缆连接，虚拟成一台逻辑交换机**统一管理和配置。

```
   物理上：                     逻辑上：
   [交换机1]                     ┌──────────────┐
      │ 堆叠线                   │   一台逻辑     │
   [交换机2]        →            │   交换机       │
      │ 堆叠线                   └──────────────┘
   [交换机3]                     统一管理、统一配置
```

| 优势 | 说明 |
|---|---|
| **简化管理** | 多台当一台管，一次配置全网生效 |
| **提高可靠性** | 一台故障，其他接管，业务不中断 |
| **便于扩展** | 加设备就是"加进堆叠"，容量线性增长 |
| **跨设备链路聚合** | 可实现跨物理设备的聚合（M-LAG） |

> 💡 **术语解释｜M-LAG（Multichassis Link Aggregation Group）**
> **跨设备链路聚合**。让**两台独立交换机**对下游表现为**一台**，下游设备可以同时连两台做聚合，实现"设备冗余 + 链路聚合"二合一，**替代传统堆叠**（避免堆叠的"一挂全挂"风险）。

### 11.4 VRRP / HSRP：网关冗余

**问题**：如果内网只有一台网关（路由器），它一挂，**全网断网**。

**答案**：用**两台网关做"主备"**，虚拟出一个"永不消失"的网关 IP。

> 💡 **术语解释｜VRRP（Virtual Router Redundancy Protocol，虚拟路由冗余协议）**
> 把**多台路由器虚拟成一台**，对外提供**一个虚拟 IP（VIP）**作为网关。主设备（Master）负责转发，备设备（Backup）待命；**主设备故障时，备设备秒级接管**。
>
> **关键点**：**终端的网关 IP 永远不变**（指向虚拟 IP），所以**切换对终端透明**。

```
       虚拟网关 IP：192.168.1.1（终端都指向它）
                    │
        ┌───────────┴───────────┐
        │                       │
   [路由器A]                [路由器B]
    Master（主）             Backup（备）
    优先级高                 优先级低
    实际转发                 待命，随时接管
        │                       │
        └───────────┬───────────┘
                    │
              内网终端（网关都填 192.168.1.1）
```

| 机制 | 说明 |
|---|---|
| **虚拟 IP（VIP）** | 终端配置的网关地址，主备共享 |
| **优先级（Priority）** | 高的当 Master（默认 100，越大越优先） |
| **抢占（Preempt）** | 原主恢复后是否抢回 Master 角色 |
| **心跳报文** | 主设备周期性发送 VRRP 通告，备设备收不到就认为主挂了，接管 |

> 💡 **术语解释｜HSRP（Hot Standby Router Protocol）**
> 思科私有的网关冗余协议，功能类似 VRRP。**VRRP 是国际标准（多厂商通用），HSRP 是思科私有。** 现在主流用 **VRRP**。

> 📌 **网关冗余的价值**：**"终端网关 IP 不变，但背后永远有一台活着的网关"**。这是**企业网络高可用的基石**。

### 11.5 高可用技术对比

| 技术 | 冗余什么 | 解决什么问题 | 典型场景 |
|---|---|---|---|
| **链路聚合** | 链路 | 带宽不足 + 链路故障 | 交换机间、服务器上联 |
| **堆叠 / M-LAG** | 设备 | 单台设备故障 + 简化管理 | 核心/汇聚双机 |
| **VRRP / HSRP** | 网关 | 网关单点故障 | 内网出口网关 |
| **双机热备** | 关键设备 | 设备整体故障 | 防火墙、负载均衡器 |
| **STP / MSTP** | 路径 | 二层环路 + 链路冗余 | 有冗余链路的二层网络 |
| **双上行** | 链路路径 | 上联链路故障 | 接入→汇聚 |

> 📌 **组合使用才是王道**：一个高可用企业网络往往**同时用**"双核心堆叠 + 链路聚合 + VRRP 网关 + MSTP 防环"。

## 12. 无线网络技术

### 12.1 802.11 协议族

> 💡 **术语解释｜802.11（IEEE 802.11）**
> IEEE 制定的**无线局域网（WLAN）标准**，也就是我们说的 **WiFi**。从 1997 年至今不断演进，速度从 2Mbps 提升到数十 Gbps。

| 标准 | Wi-Fi 代号 | 最大速率 | 频段 | 特点 |
|---|---|---|---|---|
| **802.11**（原始） | — | 2 Mbps | 2.4 GHz | 1997 年，已淘汰 |
| **802.11a** | — | 54 Mbps | 5 GHz | 抗干扰强，覆盖差 |
| **802.11b** | — | 11 Mbps | 2.4 GHz | 成本低，易干扰 |
| **802.11g** | — | 54 Mbps | 2.4 GHz | 向下兼容 b |
| **802.11n** | **Wi-Fi 4** | 600 Mbps | 2.4/5 GHz | **支持 MIMO**，多天线并发 |
| **802.11ac** | **Wi-Fi 5** | 1.3 Gbps+ | 5 GHz | 速度快，现代主流 |
| **802.11ax** | **Wi-Fi 6 / 6E** | 9.6 Gbps | 2.4/5/6 GHz | 高效率、大容量 |
| **802.11be** | **Wi-Fi 7** | 46 Gbps | 2.4/5/6 GHz | 超高速、超低延迟 |

> 💡 **术语解释｜MIMO（Multiple-Input Multiple-Output，多输入多输出）**
> 用**多根天线同时收发**数据，大幅提升速率。**MU-MIMO**（多用户 MIMO）能同时服务多个终端。这是 802.11n 之后速率暴涨的关键。

> 📌 **记忆**：**n=Wi-Fi4，ac=Wi-Fi5，ax=Wi-Fi6，be=Wi-Fi7**。**Wi-Fi 6E 是 6 的"扩展频段版"（多了 6GHz）。**

### 12.2 频段与信道

| 频段 | 速率 | 覆盖/穿墙 | 干扰 | 信道数 |
|---|---|---|---|---|
| **2.4 GHz** | 较低 | **强**（穿墙好） | **多**（微波炉、蓝牙、邻居 WiFi） | 13 个（**只有 1/6/11 不重叠**） |
| **5 GHz** | **高** | 较弱 | **少** | 更多 |
| **6 GHz**（Wi-Fi 6E/7） | 高 | 弱 | **极少** | 非常多 |

> 💡 **术语解释｜信道（Channel）**
> 无线信号传输的"频段通道"，像不同的广播频率。**信道重叠会造成干扰**，导致速度下降、断流。

**2.4GHz 的信道规划（重点）：**

```
2.4GHz 的 13 个信道，实际只有 3 个"互不重叠"：
   信道1 ──────────
        信道6 ──────────
             信道11 ──────────
   （1、6、11 之间互不干扰，是推荐的规划方案）
```

> 📌 **优化建议**：
> 1. **2.4GHz 用 1/6/11，避开重叠信道**
> 2. **5GHz 干扰少，优先部署**
> 3. **AP 密集时降低发射功率**，避免覆盖过度、互相干扰

> ⚠️ **2.4GHz 为什么慢？** 因为它**信道少（只有 3 个不重叠）+ 干扰多（家电、邻居都在用）**。所以现代设备**优先连 5GHz**，2.4GHz 只作为"穿墙补充"。

### 12.3 SSID 与广播

> 💡 **术语解释｜SSID（Service Set Identifier，服务集标识）**
> 无线网络的**名字**（你手机里看到的 "Office-WiFi"）。多个 AP 可以广播**同一个 SSID**，实现漫游。

> ⚠️ **误区**：**"隐藏 SSID 就安全"是错的。** 隐藏 SSID 只是不广播名字，攻击者用抓包工具照样能发现。**真正的安全靠加密，不靠隐藏。**

### 12.4 无线加密方式

| 加密方式 | 强度 | 是否推荐 | 说明 |
|---|---|---|---|
| **WEP** | **弱** | ❌ 禁用 | 密钥短、易破解，几分钟就能破解 |
| **WPA** | 中 | ❌ 过时 | 过渡方案（TKIP） |
| **WPA2** | **强** | ✅ 主流 | 用 **AES** 加密（CCMP） |
| **WPA3** | **更强** | ✅ 新标准 | 增强抗暴力破解（SAE），前向保密 |

> 💡 **术语解释｜WPA2 / WPA3**
> - **WPA2**：用 **AES-CCMP** 加密，是多年来的主流标准
> - **WPA3**：用 **SAE（对等实体同时认证）** 替代 WPA2 的握手，**防离线字典攻击**，并提供**前向保密**
>
> **个人版（PSK）** 用预共享密码；**企业版（802.1X）** 用账号认证（RADIUS）。

> 📌 **无线安全部署清单**：
> 1. **必须用 WPA2 或 WPA3 加密**（绝不用 WEP）
> 2. **定期更换密码**
> 3. **开启客户端隔离**（防设备互相访问，尤其公共 WiFi）
> 4. **关闭 WPS**（有漏洞）
> 5. **MAC 过滤只作辅助**（MAC 可伪造，不是安全保障）

## 13. 广域网接入方式

> 💡 **术语解释｜广域网（WAN，Wide Area Network）**
> 覆盖**大范围地理区域**（跨城市、跨国家）的网络。企业通过它**把多个分支机构连接起来**，或**接入互联网**。

### 13.1 常见接入方式

| 方式 | 原理 | 带宽/质量 | 成本 | 适用 |
|---|---|---|---|---|
| **PPPoE 拨号** | 以太网上跑 PPP，需"拨号"认证 | 中 | **低** | **家庭宽带、小型办公室** |
| **企业专线** | 运营商提供的专用线路 | 高、稳定 | 高 | 中大型企业出口 |
| **MPLS VPN** | 运营商 MPLS 网络承载的企业专网 | **极高、确定性强** | **高** | 银行、大型集团、关键业务 |
| **VPN** | 公网上建加密隧道 | 取决于公网 | 低 | 远程接入、分支互联 |
| **SD-WAN** | 软件定义，统一调度多种线路 | 灵活 | 中 | 多分支、跨国企业 |
| **5G / 4G** | 蜂窝网络 | 中 | 中 | 移动办公、临时组网、备份 |

### 13.2 PPPoE：家庭宽带为什么"要拨号"

> 💡 **术语解释｜PPPoE（Point-to-Point Protocol over Ethernet，以太网上的点对点协议）**
> 在**以太网**上实现 **PPP 拨号**的协议。运营商用它来**认证用户、分配 IP、计费**。
>
> **为什么家庭宽带要"拨号"？** 因为运营商需要**验证你是谁**（账号密码）才能给你 IP。PPPoE 就是把"账号密码认证"搬到以太网上。

**PPPoE 两个阶段：**

```
① 发现阶段（Discovery）：
   客户端广播寻找"服务集中器（BRAS）"，协商出 Session ID
② 会话阶段（Session）：
   在 PPP 会话上做认证（PAP/CHAP）+ 分配 IP + 传数据
```

> 📌 **你家路由器的"宽带拨号（PPPoE）"设置，填的就是运营商给的账号密码。** 认证通过后，运营商的 BRAS 设备给你分配一个公网 IP。

### 13.3 MPLS：企业专网的"高速路"

> 💡 **术语解释｜MPLS（Multi-Protocol Label Switching，多协议标签交换）**
> 运营商提供的一种**企业专网技术**。它在数据包前面加一个**"标签（Label）"**，中间设备**只看标签转发**（不看 IP），实现**高速、可控**的转发。

**MPLS 的标签交换原理：**

```
   传统 IP 转发：每个路由器都要查 IP 路由表（慢、逐跳决策）
   MPLS 转发：  入口打标签 → 中间设备只看标签转发（快）→ 出口去标签
```

| MPLS 优势 | 说明 |
|---|---|
| **确定性** | 走物理隔离的专用通道，**不受公网拥塞影响** |
| **低延迟** | 通常 **10ms 以内**，丢包率接近零，抖动极小 |
| **QoS 保障** | 能对关键业务（如语音、ERP）做优先级保障 |
| **SLA 承诺** | 运营商提供服务等级协议 |

| MPLS 劣势 | 说明 |
|---|---|
| **成本高** | 专线费用远高于普通宽带 |
| **开通周期长** | 要运营商上门施工，可能几周 |
| **灵活性差** | 增加分支、调整网络麻烦 |

> 📌 **MPLS 适合谁？** **银行、大型集团、跨国公司**等对**稳定性和 SLA 要求极高**的场景。

### 13.4 SD-WAN：软件定义的"智能调度"

> 💡 **术语解释｜SD-WAN（Software-Defined WAN，软件定义广域网）**
> 用**软件定义 + 集中管理**的方式，**统一调度多种底层线路**（Internet、MPLS、专线、4G/5G），根据**业务策略智能选路**。
>
> **本质**：**不是一条物理线路，而是一套"广域网管理和调度体系"。**

**SD-WAN 的四大能力：**

| 能力 | 说明 |
|---|---|
| **多线路管理** | 同时管理 Internet、MPLS、专线、5G |
| **智能选路** | 按应用类型、线路质量**动态选路**（重要业务走好线路） |
| **多线路冗余** | 一条线路故障，**自动切换**到其他线路 |
| **集中管理** | 统一平台配置所有分支节点，降低运维复杂度 |

> 💡 **术语解释｜智能选路（Intelligent Routing）**
> SD-WAN 实时探测各条线路的**延迟、丢包、抖动**，结合**应用策略**决定流量走哪条路。例如：
> - 普通网页 → 走便宜的 Internet
> - 视频会议 → 走低延迟线路
> - ERP 关键业务 → 走 MPLS
> - 某线路故障 → 自动切到备用线路

**四种组网方式的定位（一张表看懂）：**

| 技术 | 解决什么 | 定位 |
|---|---|---|
| **普通宽带** | 基础上网 | **接入资源** |
| **VPN** | 建立虚拟专用连接 | **连接方式** |
| **MPLS** | 高质量企业专网互联 | **底层网络资源** |
| **SD-WAN** | 多线路、多地点、多业务统一组网调度 | **管理调度体系** |

> 📌 **关键理解**：**它们不是替代关系，而是可以组合**。现代企业常用：**"Internet + MPLS + SD-WAN"混合架构**——核心业务走 MPLS，普通访问走 Internet，SD-WAN 统一调度。

> ⚠️ **SD-WAN 的局限**：**质量取决于底层链路**。纯互联网链路的 SD-WAN，在跨运营商、高峰时段仍可能出现延迟波动。**要确定性，还是得靠专线/MPLS。**

### 13.5 其他接入技术速览

| 技术 | 说明 |
|---|---|
| **企业专线** | 运营商提供的独享带宽专线（如 100M 专线），上下行对称、稳定 |
| **VPN（IPsec/SSL）** | 公网加密隧道，分支互联或远程接入 |
| **5G 固定无线接入** | 用 5G 替代有线宽带，适合布线困难场景 |
| **卫星接入** | 偏远地区、海上、应急通信 |
| **SDH/MSTP** | 传统传输网技术（运营商内部） |
| **PON（无源光网络）** | 光纤接入技术，家庭"光猫"用的就是它 |

## 15. 常见误区

**误区 1：集线器和交换机差不多，都是"分线器"**
✅ 正确理解：**集线器是物理层设备，广播转发、共享冲突域、半双工；交换机是二层设备，定向转发、端口独立冲突域、全双工。** 两者性能天差地别，交换机已全面取代集线器。

**误区 2：路由器比交换机快**
✅ 正确理解：**在同一网段内，交换机远快于路由器。** 交换机是硬件直转（只认 MAC），路由器要查路由表、改 TTL、重算校验和。**内网用交换机，跨网段才用路由器。**

**误区 3：三层交换机就是"交换机 + 路由器"，功能完全一样**
✅ 正确理解：三层交换机**性能极高、端口密度大，但功能相对简单**，适合**内网**；路由器**功能丰富（NAT/VPN/QoS/广域网接口），适合网络边界**。**"对内三层交换机，对外路由器"。**

**误区 4：有了防火墙就不用 IDS/IPS 了**
✅ 正确理解：**三者职责不同**——防火墙管"能不能进"（访问控制），IDS 只检测告警，IPS 检测并阻断。**现代常融合在 NGFW 里，但概念上不是一回事。**

**误区 5：正向代理和反向代理只是"方向不同"**
✅ 正确理解：核心区别是**代理谁**——**正向代理代理客户端**（服务器不知道真实客户端），**反向代理代理服务器**（客户端不知道真实服务器）。方向只是表象。

**误区 6：链路聚合后，单个文件传输速度会变成 N 倍**
✅ 正确理解：链路聚合提升的是**总吞吐量**和**可靠性**。**单个数据流仍走同一条物理链路**（受哈希算法限制），所以**单流速度不会叠加**。多条流才能跑满总带宽。

**误区 7：堆叠和链路聚合是一回事**
✅ 正确理解：**堆叠是把多台设备"变成一台"**（简化管理 + 设备冗余）；**链路聚合是把多条链路"变成一条"**（带宽 + 链路冗余）。**冗余的层次不同**（设备 vs 链路）。

**误区 8：隐藏 SSID 就能防止别人连我的 WiFi**
✅ 正确理解：**隐藏 SSID 不是安全措施。** 抓包工具能轻易发现隐藏的 SSID。**真正的安全靠 WPA2/WPA3 加密。**

**误区 9：WEP 加密够用了**
✅ 正确理解：**WEP 已被彻底攻破**，几分钟就能破解。**必须用 WPA2（AES）或 WPA3。**

**误区 10：SD-WAN 就是"便宜的 MPLS"，可以完全替代专线**
✅ 正确理解：**SD-WAN 是"管理调度体系"，不是线路。** 它的质量**取决于底层链路**。要**确定性（低延迟、低抖动）**，仍需专线/MPLS。**现代做法是混合使用。**

**误区 11：网络拓扑里"网状"一定最好**
✅ 正确理解：网状**可靠性最高但成本也最高**。**终端接入用星型，分层网络用树型，核心骨干才用网状。** 真实网络都是**混合型**。

**误区 12：核心层应该配最强的策略和最多的功能**
✅ 正确理解：**恰恰相反**。核心层承载全网流量，**越简单越快**。**复杂策略要下沉到汇聚层**，终端控制放在接入层。**"核心只管快"。**

### 任务 3：用模拟器搭建三层网络架构

**工具**：**华为 eNSP**（免费，适合学华为设备）/ **Cisco Packet Tracer**（免费，适合学思科）/ **GNS3**（更接近真实设备）

**实验目标**：搭建一个"核心 + 汇聚 + 接入"的三层架构

```
        [核心交换机 L3]
         /            \
   [汇聚1 L3]      [汇聚2 L3]     ← VLAN 网关、ACL
     /    \          /    \
 [接入1] [接入2]  [接入3] [接入4]  ← 终端接入，VLAN 划分
    │
  PC1/PC2（不同 VLAN）
```

**配置要点**：
1. 在接入交换机上**划分 VLAN**
2. 在汇聚交换机上配置 **VLAN 网关（SVI）**
3. 配置**链路聚合**（核心↔汇聚之间）
4. 配置 **VRRP**（双汇聚做网关冗余）
5. 用 **ping** 验证不同 VLAN 互通、故障切换

**验证**：断掉一台汇聚交换机，观察业务是否中断（验证 VRRP 冗余）。

### 任务 4：观察并分析一次真实的上网路径

```bash
# 跟踪到目标服务器的完整路径（每一跳都是一台路由器）
tracert www.baidu.com          # Windows
traceroute www.baidu.com       # Linux/macOS

# 查看路径中每一跳的延迟
# 观察：第一跳通常是你的网关（家用路由器），
#       后面是运营商的各级路由器，最后到达目标
```

**观察要点**：
- 第一跳（网关）的延迟（通常 <5ms）
- 运营商骨干的跳数和延迟
- 哪一跳延迟突然变大（可能有瓶颈或跨地域）

### 任务 5：盘点你身边的安全设备

**目标**：识别常见安全设备并理解其作用。

```
□ 家用路由器里的"防火墙"（NAT + 包过滤）
□ 公司网络里的防火墙（NGFW？）
□ 是否有 WAF、IDS/IPS、堡垒机？
□ 无线是否用了 WPA2/WPA3？
□ 是否开启了客户端隔离？
```

**输出**：写一份 200 字的"安全设备盘点报告"，说明每个设备防的是什么威胁。
